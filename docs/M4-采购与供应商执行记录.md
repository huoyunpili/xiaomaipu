# M4 采购与供应商执行记录

日期：2026-09-08。

本轮补齐库存补货采购：供应商资料、报价历史、采购单、供应商分批发货、实际收货入库、分次付款、关闭未收数量、采购退货和实际退款。入口位于导航栏“采购”。

## 使用流程

1. 在货盘建立商品，在“采购 → 供应商与报价”记录拿货来源。
2. 可以直接新增采购，也可以记录报价后点击“按这条报价采购”。货况和成色自由填写，成本只填单件进货成本。
3. 保存采购单后确认已向供应商下单。供应商发货数量只记在途，不增加可售库存。
4. 按每次实际收货数量入库；到货货况不同的货分次录入，每次产生独立实物组。未单独登记供应商发货也允许直接收货。
5. 实际付款、实际退款单独登记。取消未收货物时关闭剩余采购，已收到的库存保留，待退款金额在详情中提示。
6. 收货记录可“退回供应商”，只能退回该组仍可售且未被销售订单占用的数量。退货扣减库存和应付，款项到账后再登记退款。

## 数据规则

- 采购单固定供应商名称、商品名称、货况、成色和单件成本；新增报价不改历史采购、库存及销售成本。
- 新采购入库的单件成本即实际记账成本，不另加采购运费。
- 收货、退货与采购状态更新在同一事务中，失败全部回滚；提交标识防止重试重复操作，版本与行锁防止并发超收。
- 每次收货关联实物组，库存收货和采购退货流水记录采购单标识；采购资金及操作保留独立事件和审计记录。
- 采购付款不作为销售订单费用再计一次，销售仍按实际出库成本计算利润。
- 已关闭采购可继续补付已验收货款、登记退款或退回已收库存，不能继续收取已取消的货物。

## 验证与部署

完整质量检查通过：Ruff、格式、类型、Django 配置、迁移一致性与 44 项测试（含真实浏览器流程）。手机采购详情与收货表单截图已检查，无横向溢出。本机开发数据库的两个采购迁移已应用。

新增测试覆盖：分批到货及在途数量、分次付款与超付保护、取消和退款、退回已占用货物的拦截、报价变更后历史销售利润保持不变、重复提交、事务回滚、并发收货，以及手机浏览器从供应商报价到采购退货退款的完整操作。

新增 `procurement` 应用及两个向前迁移，仅增加采购相关表与约束，不改写原商品、库存和订单。升级命令：`.venv/Scripts/python.exe manage.py migrate`。已有业务数据的采购表不得通过回滚迁移直接删除。
