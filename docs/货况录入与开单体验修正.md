# 货况录入与开单体验修正

日期：2026-09-07。

用户反馈：货况录入没有数量入口；“从货盘开单”直接跳回货盘，无法理解下一步。

后续明确的优先级：**货况、成色、库存是三个核心信息**。新增及入库表单按货况、成色、数量优先展示，成色保持自定义选填但不折叠。货盘、实物及选货卡片直接显示成色和可售数量，成本等信息放在后面；未填写成色显示“未记录”。搜索支持商品及实物成色。

- 新增商品页面同时展示货况、成色、库存数量和单件进货成本，保存时创建商品与首批库存。有库存必须提供成本，允许明确填 0；没货仍可只建档。
- 2026-09-08 按实际记账习惯取消单独的采购运费输入，统一填写单件进货成本。新录入的采购运费字段为 0；历史记录保留，货盘展示历史成本与运费之和，既有订单快照不变。
- 商品与入库使用同一外层事务和幂等键，重试不重复入库，入库失败不留下半成品商品。沿用现有库存流水，不直接覆盖余额。
- “订单 → 新增订单”进入专门选商品页面，提示下一步并展示可售量；无库存时提供补录库存入口。
- 开单按“选择具体货物 → 数量与成交价 → 买家与渠道”分区，货物以完整货况卡片展示，单一可售组自动预选。不同货况仍需明确选择，已锁完的组不列为可售选项。
- 实物组提供“卖这组货”，进入时保留选择；成交总额随数量、单价变化，最终金额仍由服务端整数分计算。
- 不改变已存在商品、库存和历史订单，不新增数据库迁移。

验证：新增合并录入、幂等、整笔回滚、成本校验及页面提交测试；浏览器从合并录入、订单选货到完整成交走通。完整质量门禁 37 项测试通过，手机截图已检查。
