# 2026-09-16 问题回归与发布要求

本清单以当天最终确认的界面和业务口径为准。正式版必须运行 `scripts/check.py`；`scripts/build_release.ps1` 在打包前强制运行同一检查，再运行 `scripts/verify_release_runtime.ps1`，构建正式镜像并用隔离数据库验证迁移、重建与页面逻辑，失败不生成发行包。未提交的修改禁止打包，避免遗漏新增代码、模板或数据库迁移。

## 已固定的口径

| 项目 | 必须保持的行为 | 自动验证 |
| --- | --- | --- |
| 商品图片 | 保存图片地址；历史重建、列表漏图、首图失败、失效地址、损坏缓存均可恢复；不改变交易事实 | `test_product_images.py` |
| 待发货 | 无发货时间不显示已发货；接入前已付款但未发货的订单仍需跟进 | `test_workspace_cashflow.py` |
| 同步 | 网页、Worker、Beat 必须同时启动；列表同步后补查订单、售后详情；有限次重试；超过 10 分钟未成功同步提示数据可能过期 | `test_sync_freshness.py`、`test_sync_enrichment.py`、启动脚本就绪检查 |
| 今日回款 | 今日已完成金额＋今日剩余预计；完成后合计不减少、不重复 | `test_workspace_cashflow.py` |
| 未来三天 | 从明天零时至第四天零时，页面显示三个自然日的日期范围；按北京时间跨月、跨年、闰日计算 | `test_workspace_hardening.py` |
| 超时提示 | 无超时订单时不展示；有时说明预计时间已过但订单未完成，不宣称平台欠款 | `test_workspace_hardening.py` |
| 已确认退款 | 用户确认的缺金额退款保留已退款；不伪造退款金额、不自动标记供应商货款已追回 | `test_refund_confirmation.py` |
| 追回金额 | 仅明确为退货退款、尚未追回的供应商成本；包括退款中和已退款；不统计仅退款及未知类型 | `test_refund_recovery.py` |
| 快速追回 | 卡片下拉＋确定；成功后变色、失败不假成功、可改回、只修改追回字段、同步后保留 | `test_refund_recovery.py`、`test_daily_regressions_browser.py` |
| 成色与缺失字段 | 有信息才显示；无成色填写框；隐藏“平台未提供”和冗余暂停提示 | `test_product_condition.py`、浏览器回归 |
| 成本售价参考 | 展示同商品最近已付款订单单件实付折算价、件数和总额，不拿未付款单作参考 | `test_cost_sale_price.py` |

## 正式版检查

1. 使用干净且完整提交的源码；不能沿用今天修复前生成的安装包或镜像。
2. `uv sync --frozen`，准备隔离测试数据库与 Playwright 浏览器后运行完整检查。Windows 本机可设 `PLAYWRIGHT_CHANNEL=chrome`。
3. 发行包必须包含工作台、图片代理、版本化静态资源、迁移 `0009` 和 `0010`，以及上述回归测试。
4. 安装、升级、恢复均执行数据库迁移和工作台重建；用户确认的退款、追回状态及图片元数据必须保留。
5. 启动完成不能只以网页 HTTP 200 判断；确认 Worker/Beat 运行并且 Worker 能响应任务检查。
6. 首次配置平台连接后核对最近同步时间；金额明细必须能与汇总核对一致。

接口短时不可用或平台缺字段不能完全消除；界面必须如实反映同步状态，不猜造金额、日期、成色。用户填写的供应商、成本及人工确认应保存在数据库中，随备份恢复，不依赖本机临时脚本。
