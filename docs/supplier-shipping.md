# 供货商文字清单、发货与视频回传

## 操作

1. 待发货页勾选订单、供货商（可多选），导出后按供货商分别生成清单。
2. 打开清单，复制文字或下载 TXT 发给对应供货商。发货清单不再生成或展示 PNG 图片。
3. 供货商打开专属链接，每单独立保存视频和快递单号。保存单号即授权系统提交闲鱼发货，页面明确标注按钮作用。
4. 视频逐个上传，完整落盘、SHA-256 回读校验、数据库记录成功后才显示保存成功；同内容重试去重，每单最多 10 个、每个最大 60MB。
5. 平台物流回查一致且有发货时间才显示发货成功；超时或不确定结果不自动重复提交。
6. 店主在订单详情下载原视频，查看保存时间、文件大小和校验值。哈希证明文件一致性，不等同于证明拍摄内容真实或保证纠纷判定。

## 公网入口

先运行完整本地后台和 Worker/Beat，再运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_supplier.ps1
```

要求 `.local/tools/cloudflared.exe` 来自 Cloudflare 官方发布；如果存在已校验的 `.local/tools/cloudflared-verified.exe`，脚本优先使用它。守护使用状态文件中记录的本机回环端口；新环境默认 18766，端口被占用时不会停止其他程序。专用 Waitress 服务通过健康检查后，Quick Tunnel 只连接这个端口；绝不能指向管理后台 8765。

网关使用 `app.config.settings.supplier` 和独立 URL 配置，不提供后台、登录或视频下载路由。具有独立 CSRF Cookie、HTTPS、请求体上限、连接数限制和无敏感 URL 的日志。

临时隧道无可用性保证。进程持续运行时保持当前网址；重建隧道可能改变域名，后台保存新网址后需重新复制链接发给供货商。电脑必须保持开机联网、不休眠。网关和隧道不随普通后台重启而自动重建，以免中断上传或使旧链接失效。

链接随机生成，30 天到期，可由店主撤销；每次操作校验订单是否属于该批次、供货商及当前店铺。该链接验证访问凭证，不验证供货商本人。公网页面展示本清单的商品、订单尾号、收货人、电话及完整地址，支持复制收货信息；不显示供货商姓名、成本或其他供应商订单。

## 平台发货

使用闲管家 `POST /api/open/order/ship`，快递列表从 `/api/open/express/companies` 读取。需账号具有接口权限，并在闲管家设置正确的默认发货地址；本版省略寄件人字段，使用平台默认地址，不虚构寄件人。多供货商寄件地址不同时，需后续扩展按供货商配置真实地址。

提交前回查平台，核对商品、收件信息、备注和退款状态，只对平台明确待发货的订单提交。保存记录是持久队列；消息投递失败由每 30 秒巡检补处理。跨批次同订单只允许一个当前发货请求。`SENDING/UNKNOWN` 只回查，不自动重发；网络断开或服务崩溃后不会将未确认的请求当成成功。

未使用真实订单和虚构快递单号测试写入。实际首次发货需用真实已发出包裹验证账号权限、默认寄件地址及平台回查结果。

## 存储与备份

原视频存放在 `PRIVATE_MEDIA_ROOT/supplier-evidence/<订单UUID>/`，不转码、不覆盖；订单详情提供按原文件名下载。备份命令 `manage.py backup_local` 包含此目录及数据库。导出 PNG 清理规则不删除视频。迁移 `0011` 创建独立上传授权、发货提交和视频记录表。

回归测试覆盖供应商隔离、改派/撤销/过期、CSRF、网关无法访问后台、重复上传、落盘和下载、退款拦截、单号重复提交、平台超时不重发，以及手机和桌面的上传失败重试、分单保存和刷新保留。
