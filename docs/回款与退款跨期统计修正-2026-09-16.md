# 回款与退款跨期统计修正

## 原因

自动同步起始日为北京时间 2026-09-11。平台按更新时间返回了更早下单的订单，但工作台按下单时间将这些订单排除。两笔仍在退款处理中的旧单，以及两笔今天完成的旧单，因而没有出现在经营视图。

原退款入口同时包含「退款处理中」和「已退款、供应商货款未追回」，导致列表被误解为仍需给客户退款。原「今日参考回款」只统计未完成订单的预测日期，未提供今日已完成订单的单独入口。

## 修正口径

- 保留同步起始日与平台原始范围标记。
- 接入前已付款的待完成、退款处理中订单继续跟进；接入后完成或全额退款成功的旧单也纳入工作台，来源标记为 `API_CARRY`。
- 接入前已完结且无后续义务的历史单仍不自动导入。历史待发货订单仍沿用原人工导入流程。
- 已建立的工作台订单后续正常更新，保留订单号去重、成本快照、人工备注和供应商信息。
- 平台状态为已发货但缺少发货时间的订单保留「待完成」和担保金额；不编造回款日期，独立显示无法预测的数量与金额。完成时间与已发货状态冲突仍进入待核对。
- 新增「今日已完成订单 · 回款核对」：按北京时间的确认收货日汇总订单实付，可进入一致口径的明细。此数值不是资金账单的净到账额，不将完成时间冒充到账时间。
- 日期预测改称「预计待回款」，仅包含仍未完成的正常订单。退款处理中停止预测，完成后从预测中移除。
- 退款页默认仅显示处理中；另设供应商待追回、客户退款已完成、全部售后。退款进度直接显示平台已知阶段。
