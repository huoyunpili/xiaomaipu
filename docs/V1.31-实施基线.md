# PRD V1.31 实施基线

本次实现以 PRD V1.31 为唯一产品范围。旧 T0–T5 记录保留为历史，不代表新版本验收通过。

## 技术方案

沿用 Django、PostgreSQL、Celery 和现有本地发行脚本。新增 workbench 业务模块，独立于旧采购库存模型；平台订单入库后自动投影，不再要求用户逐单转成销售草稿。旧账及库存数据不删除。

| 实体 | 职责 |
|---|---|
| Trade | 平台/导入订单、状态、收件信息、时间、成本快照、本地售后备注 |
| ProductCost | 商品/规格匹配键、成本版本、默认供应商 |
| ExportBatch | 不可变的发货或退款清单快照、供应商、生成时间、状态变化提示 |
| AuditEvent | 成本更正、运费修改、退款追回确认的操作记录 |

金额统一使用整数分；1.6% 平台费逐单四舍五入到分，汇总逐单结果。北京时间自然日筛选；预计按 pay_time，实际按 confirm_time。全额退款利润为零，选填运费损失单列。缺成本不按零成本计算。

担保金额仅包括已付款、未完成、未关闭、未全额退款订单；退款申请计风险而非完成退款。正常发货参考回款日为 consign_time + 10×24 小时；退款中暂停参考。未知平台状态保持待核对，不能自动变成交易成功。

历史订单使用 UTF-8 CSV 模板导入，同一店铺订单号唯一；后续同步更新平台字段，不覆盖用户成本快照和售后备注。补填商品成本一次会补齐同类型缺成本订单；更改当前成本仅影响新订单，旧快照更正必须填写原因。

发货导出前刷新所选 API 订单，网络失败不生成新发货单；状态改变后重新检查并排除已发货/退款/关闭订单。导出按供应商生成 PNG，使用本地字体，不请求远程图片或上传地址。批次保存在私有数据库，下载必须登录。历史批次不会因为同步而删除。

前端使用 Django 模板、响应式 CSS、少量原生 JavaScript；主导航为工作台、待发货、待完成、退款售后、利润统计、全部订单、设置。图片仅用已同步的安全 HTTP(S) URL，失败时占位，金额、状态和主要操作保持文字可读。手机核心操作不依赖横向滚动。

本版本所有能力免费；无激活码、公众号绑定、付费服务或授权服务器。API 配置保存在本机，旧连接起始日保持不变。升级先备份，再迁移，再重启；不调用退款审批、发货等平台写接口。

## 实施顺序

1. R1：订单模型、状态投影、API 同步接入、旧快照回填。
2. R2：商品成本版本、自动快照、利润/担保计算、退款追回和可审计更正。
3. R3：七个主页面、日期筛选、商品图片、逐单公式与汇总。
4. R4：发货/退款 PNG、过期批次、CSV 导入与导出、设置和安装引导。
5. R5：迁移与业务测试、浏览器桌面/手机验证、备份升级和执行记录。

## 验证要求

- 覆盖 PRD A1–A11，特别是退款即时扣减、完成订单移出担保、历史成本不被覆盖、时间区间边界和重复导入。
- 导出必须验证访问权限、重新同步失败、状态变化、多个供应商、中文长地址和移动端布局。
- 运行 Django 检查、迁移检查、ruff、类型检查和现有适用回归测试；修改页面导致旧 UI 断言过时则更新断言，不能忽略业务回归。
- 真实平台字段的枚举如未有证据，不宣称已验证；记录来源与限制。现有生产订单不作为测试修改对象。
