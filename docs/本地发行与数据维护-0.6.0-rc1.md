# 本地发行与数据维护：0.6.0 RC1

本版对应 PRD V1.31，面向本机单店经营，全部功能免费，无激活码或订单数量限制。旧采购、库存和销售记录继续保留，日常入口改为 API 订单工作台。

## 首次安装

启动 Docker Desktop，解压完整源码包，在项目目录打开 Windows PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Install
```

首次构建需要联网下载镜像和锁定依赖。脚本生成随机密钥，在 `%LOCALAPPDATA%/XianyuSeller` 保存数据库、私有文件、配置和备份。打开 `http://127.0.0.1:8765`，按页面提示创建自己的店主账号；没有默认账号密码。

自定义目录和端口示例：

```powershell
./scripts/local_release.ps1 -Action Install -DataDir 'D:/我的小卖铺 数据' -Port 8766
```

以后每个管理命令都使用相同的 `-DataDir`。数据目录与源码目录应分开保管。

## 日常使用

1. 在设置连接闲管家：先在经营目录的 `config.env` 填写自己的 API 配置，再执行 Restart；打开“设置 → 闲管家 API”验证连接和确认同步起始日。
2. API 接入日起的订单自动进入工作台；此前订单使用设置中的 CSV 模板导入。重复订单跳过，格式错误整批回滚。
3. 在商品配置为每种类型填写成本、默认供应商、微信备注和发货备注。已有订单成本快照不会被后续调价改写。
4. 待发货页选择订单和供货商，导出可复制的文字发货单或 TXT。系统先刷新所选订单，退款或已发货订单不应继续发货。旧清单提示变化时先核对供应商。供货商上传链接需要另外运行专用网关，当前 Docker 安装不自动部署该公网入口，见 [供货商协作说明](supplier-shipping.md)。
5. 在退款售后登记实际发生的运费损失及供应商货款追回结果。确认追回后移出默认待办，历史仍可查看，也可撤销误确认。
6. 首页担保与参考回款可进入明细；参考日期默认发货后 10×24 小时，退款中暂停，仅供经营安排。完成时间来自平台实际确认。
7. 利润页选择预计/实际和日期区间，核对逐单公式、缺成本订单、运费损失和导出。费率按逐单 1.6% 四舍五入计算。

## 启停和升级

```powershell
./scripts/local_release.ps1 -Action Status
./scripts/local_release.ps1 -Action Start
./scripts/local_release.ps1 -Action Stop
./scripts/local_release.ps1 -Action Restart
./scripts/local_release.ps1 -Action Upgrade
```

关闭浏览器不影响后台同步；Stop 停止服务并保留数据。升级使用新源码中的管理脚本，先备份已有数据库，再构建新镜像、迁移和启动。`0007_product_shop` 拆分跨店配置后不支持逆向合并，回退时恢复升级前备份。

## 备份与恢复

```powershell
./scripts/local_release.ps1 -Action Backup
./scripts/local_release.ps1 -Action Restore -BackupPath '完整数据目录/backups/备份目录名' -ConfirmRestore
```

备份会暂时停止业务写入，导出数据库、复制私有文件、恢复到临时库并比较逐表内容摘要。恢复前先检查备份文件和附件哈希，并自动备份当前状态；恢复后再次比较内容、执行迁移和业务核对。

新版备份清单含 `content_verified=true`；旧版备份按原有文件哈希规则兼容。备份不包含 `config.env`，应另行安全保存自己的配置。图片保留期限在设置中单独调整，清理图片不会删除历史批次快照。

```powershell
./scripts/local_release.ps1 -Action ScheduleBackup
./scripts/local_release.ps1 -Action RemoveBackupSchedule
```

定时备份为每天 03:00；关机时无法执行，下一次 Start 会检查是否需要补备。

## 验证与故障定位

### 升级后历史订单没有商品图片

旧版平台快照没有保存图片地址，直接回填的历史订单会显示占位图。可在项目开发环境执行 `.venv\Scripts\python.exe manage.py rebuild_workspace --refresh-missing-images`，通过已配置的只读平台详情接口补齐。命令跳过已有图片，只处理本地已纳入工作台的订单；失败保留订单并统计数量，可以再次执行。接口未提供图片的订单仍显示占位图。

商品图首次访问后保存至私有数据目录的 `product-images` 子目录，后续页面通过本机、登录保护的图片接口读取缓存。旧 HTTP 地址会转为固定平台图片域名的 HTTPS 请求；仅允许该域名，不跟随重定向，限制图片格式与大小。备份私有数据时会一并保留图片缓存。首次下载失败显示“图片暂不可用”，可以稍后刷新重试。

### “待核对”代表什么

这是订单状态暂时无法可靠判定的提示，不是缺少商品成本或供应商。具体原因显示在订单卡片上，例如付款时间缺失、退款金额不符合整单退款，或平台同一版本的已有字段发生矛盾。列表未提供、详情后来补充的字段允许合并，不再误判为冲突；已有金额和状态真正矛盾时仍保留原值并提示核对。

```powershell
./scripts/local_release.ps1 -Action Validate
```

端口占用时换用空闲端口；Docker 不可用时先启动 Docker Desktop。API 失败不删除历史数据和已生成清单。应用日志排除任意请求/错误文本，访问日志仅记录状态码与耗时。

新环境安装、真实镜像运行及最终源码包的验收结果以技术手册和实施计划中的最新执行记录为准。隔离数据库的升级恢复证据见 [V1.31 升级恢复记录](V1.31-升级恢复执行记录.md)；它不能单独证明所有目标电脑或所有真实 API 状态均已验证。
