# 供货商上传服务运行说明

当前 Windows 测试环境：运行 `scripts/start_supplier.ps1` 启动隐藏的后台守护。重复运行会复用守护，不重启上传服务或隧道。`scripts/start_local.ps1` 启动后台成功后也会调用它。

守护每 10 秒检查一次上传入口。上传进程退出且端口空闲时，重新启动同一端口，保留仍在运行的隧道和网址。端口被占用但健康检查失败时记录错误，不强行中断可能正在上传的文件。隧道进程退出后重新创建临时隧道，将新地址保存到后台；旧链接无法恢复，需要重新复制发货单中的链接发给供货商。网络短暂断开由 cloudflared 自行重连，不因为外网健康检查失败反复更换网址。

状态文件：`.local/supplier-runtime.json`。守护日志：`.local/supplier-watch.log`；启动错误：`.local/supplier-watch.err.log`；上传服务错误：`.local/supplier.err.log`；隧道连接错误：`.local/supplier-tunnel.err.log`。状态文件中的 gateway 可能为 Python 启动器 PID，监听进程以端口实际占用者为准。

验证命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_supplier_supervisor.ps1`。使用独立本地端口和模拟隧道记录，验证上传进程启动、退出后恢复及网址保留；不调用平台发货接口，不中断实际公网隧道。

## 迁到家用电脑时

本次只启用了当前测试电脑的后台守护，没有安装开机服务，也没有修改电脑的睡眠设置。关闭调试窗口不影响独立守护；电脑注销、重启后需要重新启动。正式搬迁时需一起完成：

1. 安装 Python/依赖及 cloudflared，恢复数据库与私有视频目录，验证已有订单的视频能下载。
2. 配置主后台、任务队列、数据库、上传守护随系统启动或登录启动，并验证重启恢复；目前正式版 Docker 编排尚未包含公网上传守护，不可仅启动 Docker 就认为上传入口已部署。
3. 关闭自动睡眠，保持联网和足够磁盘空间；关闭显示器不影响服务。
4. 建立新临时隧道，重新发送新链接，从另一台设备验证视频上传及本地文件；真实发货另用已确认可发的一单验证。

免费临时入口没有可用性保证。电脑开机、联网、服务运行是必要条件；守护能恢复进程退出，不能保证断电、断网或隧道提供方故障期间仍可访问。意外中断的上传需供货商重试，守护不承诺续传。
