# 本地快递公司识别

规则唯一入口：`app/workbench/courier_rules.py`，通过页面 JSON 交给浏览器执行。不调用外部识别服务，不收接口费。识别仅为可修改的建议，不能证明单号真实、包裹已寄出或物流归属。

| 公司 | 当前自动匹配范围 | 校验依据/边界 |
| --- | --- | --- |
| 顺丰 | SF + 13 位数字 | 官方示例及本机历史样本 |
| 圆通 | YT + 13 位数字 | 官方示例及本机历史样本 |
| 中通 | 790 或 791 开头，共 14 位数字 | 本机已有平台物流记录；不泛化所有 7 开头单号 |
| 申通 | 77 开头，共 15 位数字 | 常用号段启发式，尚无本机历史样本验证；用户可纠正 |
| 京东 | JD 或 JDL + 12—13 位数字 | 字母前缀启发式，不涵盖全部京东格式 |
| 极兔 | JT + 13 位数字 | 不把纯数字单号统一当极兔 |
| 德邦快递 | DPK + 12 位数字 | 使用平台 `debangkuaidi`，不混用德邦物流代码 |
| 韵达 | YD + 12 位数字 | 不因数字单号长度相同就自动选韵达 |
| EMS | E + 1 个字母 + 9 位数字 + CN | 仅中国邮政 EMS 格式建议，不泛化所有国际邮政件；不是校验码或物流真实性验证 |
| 旧式纯数字 | 共 12 位 | 可能对应多家公司，只提示候选，不自动选择 |

2026-09-17 本机只读汇总：圆通 41 条、顺丰 7 条、中通 15 条符合上述格式。这只是本机样本，不代表全国覆盖率或准确率。申通规则应在首批真实单号回传后进一步核对，不声称已取得承运商完整编码规范。

参考：[圆通开放平台示例](https://open.yto.net.cn/interfaceDocument/menu251/submenu258)、[顺丰官方操作手册](https://hd-file01-ms.sf-express.com/pdf/顺店通操作手册V2.2.9.pdf)。公开第三方规则存在长度不一致的问题，不能不经校验直接复制为权威规则。

输入时忽略首尾空格和字母大小写用于匹配，不擅自删除单号内部字符。只自动选择平台公司列表中存在且唯一命中的代码；多个候选、未知格式、公司列表缺项均手动选择。手动纠正后保持选择；修改单号则清除旧选择、重新匹配，防止沿用上个单号的公司。刷新已有发货记录不重新识别或覆盖。

扩展号段前核对平台已确认的真实记录及冲突样本，更新规则和回归测试；不要从一次人工选择自动生成全局号段规则。后端仍校验公司代码，并在真实发货后回查物流一致性。

新增字母前缀规则参考[公开识别规则示例](https://gist.github.com/shallowlong/7d5501b92666742df0b9c5bda03d0a17)和[开源项目的京东示例](https://github.com/kodephp/express-api)。这些是候选识别经验，不是承运商完整规范。已核对本账号平台公司列表包含上述代码，使用合成号码测试正例和错长度、错后缀反例；新增五家尚无本机真实单号样本验证，不承诺覆盖率。
