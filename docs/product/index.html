小卖家的本地经营后台

发货有条理，
钱款有着落。

为经营闲鱼实物商品的小卖家，把供货商发货、视频留证、退款追款和订单利润，放进一个顺手的工作台。

开始配置与试用 →看一笔订单怎么走完

适合：自己经营小店、通过微信与供货商协作、需要垫付采购款并逐单核算的实物卖家。

五大亮点

每天最费心的事，
放到同一条流程里。

从发出清单到收回钱款，减少在聊天记录、表格和文件夹之间反复查找。

01 / 供货商协作与视频留证

把清单发出去，
让单号和视频回到订单里。

按供货商生成可复制的文字清单，商品、规格、数量和收货信息一起交代清楚。供货商点开专属链接，就能逐单处理。

  • 填快递单号，核对识别出的快递公司。
  • 明确点击“保存单号并提交发货”，经闲管家接口回传平台。
  • 视频可分次补传，保存在店主电脑，并关联对应订单。

一个订单，一处查找：发了什么、单号是什么、视频在哪里。

需要 API 发货权限和公网上传入口。专属链接只发给对应供货商。

卖家导出文字清单 + 专属链接
供货商回传快递单号 + 发货前视频
平台发货接口提交，回查结果
本地留存按订单查找原视频
02 / 售后货款追回

客户退完款，
供货商的钱也别忘了收。

客户退款进度与供货商货款追回分开管理。退货退款订单上选择“未追回 / 已追回”，确认后更新状态。

  • 未追回用红色提醒，已追回显示绿色。
  • 汇总尚未追回的退货退款货款。
  • 成本不完整时提示补齐，未知金额不当作零。

少靠记忆，知道还有哪笔采购款需要跟进。

03 / 回款安排

钱什么时候回来，
进货之前心里有数。

今日合计展示今日已完成订单金额与今日剩余预计回款；未来三天从明天起算，帮助安排近期周转。

  • 已完成与预计分开展示，金额可进入明细。
  • 默认按发货后 10 天估算，可在设置中调整。
  • 实际到账金额和时间，以平台资金账单为准。

把回款时间纳入日常安排，不只盯着销售额。

04 / 逐单利润

一个利润数字，
能追到每一笔计算。

客户实付、商品成本、平台费和订单利润一项项展开。按付款日期看预计利润，按成交完成日期看实际利润，也可以导出 CSV。

  • 成本按订单留存，后续调价不改写已有快照。
  • 缺成本的订单单列，补齐后再纳入合计。
  • 售后运费损失单列，方便核对。

先把账算明白，再判断哪些商品值得继续做。

05 / 经营工作台

打开小卖铺，
先知道今天处理什么。

待发货、担保中金额、退款和利润集中展示。进入订单后，直接查看商品图片、名称、已有规格和成色。

  • 从汇总进入订单，核对金额与状态。
  • 商品成本和默认供货商集中维护。
  • 按供货商导出文字发货清单，方便复制给对方。

每天先处理发货和售后，再看资金与利润。

实际怎么用

跟着一笔订单，
把流程走一遍。

下面用一笔实物商品订单说明操作。商品和金额均为演示示例，界面截图由实际系统使用演示数据生成。

演示案例 / 一件蓝牙耳机，由供货商代发

订单进来了，先确认商品与成本。

客户实付¥200.00商品成本¥150.00数量1 件

  1. 卖家：同步订单，补齐经营信息

    在“设置 → 闲管家 API”验证店铺并同步。到“商品与供应商”维护成本和默认供货商；在待发货中核对商品、规格、数量与收货资料。

  2. 卖家：生成文字清单，发给对应供货商

    勾选订单与供货商，导出清单。复制文字及上传链接发送给对方；多家供货商分别收到自己的清单。

    看看文字清单的实际样子

  3. 供货商：核对收货信息，回传单号与视频

    打开链接，按订单复制收货信息。输入单号并核对快递公司，点击“保存单号并提交发货”。选择发货前视频，点击“保存所选视频”；无需一次传完全部订单。

  4. 卖家：确认发货结果，按订单查找视频

    检查系统返回的平台发货结果；如果提示失败或待确认，按提示核对后处理。视频显示保存成功后，可从后台订单详情查找并下载。

路径 A / 正常成交

看回款，再核对这一单的利润。

发货后查看预计回款；平台确认完成后，按完成日期纳入实际利润。示例按当前 1.6% 平台费参考计算：

¥46.80 订单利润

200 − 150 − 3.20 = 46.80 元。该例未发生额外运费、退款及其他经营开支。

路径 B / 发生退货退款

客户退款与供货商退钱，分别跟进。

在“退款售后”查看客户退款进度。假设采购款 150 元尚未退回，继续保留“未追回”；核实供货商已退钱后，选择“已追回”并确认。

未追回 → 已追回

登记状态不代替实际转账。发生商品争议时，从对应订单下载发货前视频，整理举证材料。

配置指南

按需要启用，
从自己的第一笔订单开始。

当前为 Windows 本地社区测试版，需要在自己的电脑部署。先选择试用范围，再按步骤配置。

准备工作：一台可联网的 Windows 电脑、已启动的 Docker Desktop，以及自己的闲管家应用配置与店铺授权。只安装页面不代表已经接入订单；平台发货还需要对应接口权限。外部服务费用以提供方为准。

A · 先试用经营后台

安装并启动 Docker Desktop。从 GitHub 仓库选择 Code → Download ZIP，解压完整项目，在项目文件夹中打开 PowerShell，执行：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Install

首次安装会下载依赖并初始化数据库。完成后打开 http://127.0.0.1:8765，按提示创建自己的店主账号，没有默认账号密码。

默认数据目录为 %LOCALAPPDATA%\XianyuSeller。将自己的 XGJ_APP_KEY 与 XGJ_APP_SECRET 写入该目录的 config.env，保留其中已有配置，然后重启：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Restart

这条路径先体验经营后台。若需要供货商从手机上传，请选择 B 路径；不要同时启动两套占用相同端口的环境。已有数据的切换需要备份迁移，不是重新安装即可自动搬过去。

B · 完整供货商协作

准备 Python 3.12 或 3.13、uv、已启动的 Docker Desktop。下载完整项目，在独立目录打开 PowerShell：

uv sync --frozen
docker compose -f deployment/compose.yaml up -d --wait
uv run python manage.py migrate
uv run python manage.py bootstrap

首次配置时，将项目里的 .env.example 复制为 .env.local，填写自己的应用 Key 和 Secret，保留其他默认本地连接配置。已有 .env.local 时直接编辑，不要覆盖。

XGJ_APP_KEY=填写自己的应用Key
XGJ_APP_SECRET=填写自己的应用Secret
XGJ_BASE_URL=https://open.goofish.pro

启动主后台与同步进程：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1

打开 http://127.0.0.1:8765 创建店主账号。修改配置后，用同一命令加 -Restart 重启后台和同步进程。

启用供货商公网入口

  1. 从 Cloudflare 官方发布页下载适合电脑架构的 Windows 可执行文件。
  2. 在项目下创建 .local\tools 文件夹，将文件命名为 cloudflared.exe 放入其中。
  3. 运行下面的启动命令，再去待发货页面导出清单。系统会将当前公网地址用于供货商链接。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_supplier.ps1

临时入口无需自有域名。电脑应保持开机、联网、不休眠，服务也须运行。重建隧道会更换网址，需要重新复制清单链接发送。管理后台的 8765 端口仅在本机使用。

安装完成后，把这些信息配好。

01 · 连接店铺与同步订单

打开“设置 → 闲管家 API”，点击“验证授权店铺”。按页面提示核对或确认同步起始日，点击“立即同步”；需要自动更新时开启“每 5 分钟同步”。

看到订单后，与平台核对几笔待发货、已完成和退款记录。更早的历史订单，可按“设置 → 历史订单导入”提供的 CSV 模板补入；仅修改起始日不能保证接口提供全部历史数据。

02 · 配置商品成本与供货商

打开“设置 → 商品与供应商”，按商品类型维护单件成本、默认供货商、微信备注名称和默认发货备注。已有商品规格与成色直接用于辨认，不需要重复编造。

先补齐几笔准备测试的订单成本，再核对利润明细。缺成本订单会单独展示，不会按零成本计入利润。

03 · 配置发货地址与接口权限

平台发货需要闲管家账号具备对应授权和接口权限。寄件地址有两种方式：在闲管家保存默认发货地址；或在本地配置中完整填写以下六项。全部留空时使用平台默认地址，不要只填一部分。

XGJ_SHIP_NAME=
XGJ_SHIP_MOBILE=
XGJ_SHIP_PROV_NAME=
XGJ_SHIP_CITY_NAME=
XGJ_SHIP_AREA_NAME=
XGJ_SHIP_ADDRESS=

A 路径编辑数据目录的 config.env 并 Restart；B 路径编辑项目 .env.local 后执行 scripts/start_local.ps1 -Restart。首次提交应选择一笔确实已准备发货的真实订单，用真实单号核对平台结果。

04 · 设置回款参考，核对利润口径

在“设置 → 统一回款参考规则”调整参考天数，默认发货后 10 天。已完成订单依据平台实际确认时间统计；预计回款不等于账户实际入账。

当前版本的平台费参考为客户实付的 1.6%，逐单四舍五入到分；这不是所有店铺的通用费率，暂未提供通用费率配置界面。若你的规则不同，先反馈或调整实现再依赖利润结果。税费、人工等其他经营支出未自动全部计入。

05 · 找到视频，保管经营数据

B 路径默认私有文件目录为项目下 .local\private-media；可通过 PRIVATE_MEDIA_ROOT 调整。视频与订单关联，日常从订单详情查找下载，无需记住磁盘文件名。每个视频最多 60 MB，每单最多 10 个，页面显示保存成功后再退出。

A 路径的数据由 %LOCALAPPDATA%\XianyuSeller 管理，可使用发行脚本备份：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Backup

上面的备份命令适用于 A 路径。B 路径需另行备份 PostgreSQL 数据库、私有文件目录和本地配置；只复制源码无法保留完整业务数据。迁移到家用电脑后，还需验证服务重启恢复和已有视频下载。
