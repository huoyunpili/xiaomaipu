适合：自己经营小店、通过微信与供货商协作、需要垫付采购款并逐单核算的实物卖家。

五大亮点

每天最费心的事，
放到同一条流程里。

从发出清单到收回钱款，减少在聊天记录、表格和文件夹之间反复查找。

01 / 供货商文字清单

把清单整理好，
复制后直接发给供货商。

按供货商生成文字清单，订单号、商品、规格、数量和收货信息一次交代清楚。

  • 一键复制整份清单。
  • 需要留档时下载 TXT。
  • 生成清单不会自动提交平台发货。

不需要公网入口、中继、域名或额外账户。

正式版不生成供货商链接，也不接收单号和视频。

02 / 售后货款追回

客户退完款，
供货商的钱也别忘了收。

客户退款进度与供货商货款追回分开管理。退货退款订单上选择“未追回 / 已追回”，确认后更新状态。

  • 未追回用红色提醒，已追回显示绿色。
  • 汇总尚未追回的退货退款货款。
  • 成本不完整时提示补齐，未知金额不当作零。

少靠记忆，知道还有哪笔采购款需要跟进。

03 / 回款安排

钱什么时候回来，
进货之前心里有数。

今日合计展示今日已完成订单金额与今日剩余预计回款；未来三天从明天起算，帮助安排近期周转。

  • 已完成与预计分开展示，金额可进入明细。
  • 默认按发货后 10 天估算，可在设置中调整。
  • 实际到账金额和时间，以平台资金账单为准。

把回款时间纳入日常安排，不只盯着销售额。

04 / 逐单利润

一个利润数字，
能追到每一笔计算。

客户实付、商品成本、平台费和订单利润一项项展开。按付款日期看预计利润，按成交完成日期看实际利润，也可以导出 CSV。

  • 成本按订单留存，后续调价不改写已有快照。
  • 缺成本的订单单列，补齐后再纳入合计。
  • 售后运费损失单列，方便核对。

先把账算明白，再判断哪些商品值得继续做。

05 / 经营工作台

打开鱼管家，
先知道今天处理什么。

待发货、担保中金额、退款和利润集中展示。进入订单后，直接查看商品图片、名称、已有规格和成色。

  • 从汇总进入订单，核对金额与状态。
  • 商品成本和默认供货商集中维护。
  • 按供货商导出文字发货清单，方便复制给对方。

每天先处理发货和售后，再看资金与利润。

实际怎么用

跟着一笔订单，
把流程走一遍。

下面用一笔实物商品订单说明操作。商品和金额均为演示示例，界面截图由实际系统使用演示数据生成。

演示案例 / 一件蓝牙耳机，由供货商代发

订单进来了，先确认商品与成本。

客户实付¥200.00商品成本¥150.00数量1 件

  1. 卖家：同步订单，补齐经营信息

    在“设置 → 闲管家 API”验证店铺并同步。到“商品与供应商”维护成本和默认供货商；在待发货中核对商品、规格、数量与收货资料。

  2. 卖家：生成文字清单

    勾选订单与供货商，导出清单。多家供货商会分别生成自己的文字内容。

  3. 卖家：复制或下载后发送

    点击“复制整份清单”，或下载 TXT 留档，再通过常用聊天工具发给对应供货商。

  4. 卖家：回到平台核对后续状态

    鱼管家不接收供货商单号或视频，也不会自动提交发货。后续操作在平台完成，再同步订单状态。

路径 A / 正常成交

看回款，再核对这一单的利润。

发货后查看预计回款；平台确认完成后，按完成日期纳入实际利润。示例按当前 1.6% 平台费参考计算：

¥46.80 订单利润

200 − 150 − 3.20 = 46.80 元。该例未发生额外运费、退款及其他经营开支。

路径 B / 发生退货退款

客户退款与供货商退钱，分别跟进。

在“退款售后”查看客户退款进度。假设采购款 150 元尚未退回，继续保留“未追回”；核实供货商已退钱后，选择“已追回”并确认。

未追回 → 已追回

登记状态不代替实际转账，纠纷材料继续由店主在自己的平台和本地文件中保管。

安装指南

一个安装包，
完整功能一次装好。

Windows 本地版不再区分基础版和完整协作版，也不要求用户安装开发工具。

准备工作：一台 64 位 Windows 电脑和网络连接。首次同步需要自己的闲管家应用配置、店铺授权及订单查询权限。

双击安装，完成后直接使用

  1. 从 GitHub Releases 下载 鱼管家-0.6.0-安装程序.exe。
  2. 双击安装程序。内置 Python、PostgreSQL 和任务队列，无需安装 Docker、uv 或其他组件。
  3. 安装完成后浏览器自动打开 http://127.0.0.1:8765，按提示创建自己的店主账号；没有默认账号密码。

以后从开始菜单打开“鱼管家”即可，登录 Windows 后也会自动启动。订单和私有配置保存在 %LOCALAPPDATA%\XianyuSeller，升级或卸载程序不会主动删除经营数据。

安装完成后，把这些信息配好。

01 · 连接店铺与同步订单

打开“设置 → 闲管家 API”，点击“验证授权店铺”。按页面提示核对或确认同步起始日，点击“立即同步”；需要自动更新时开启“每 5 分钟同步”。

更早的订单先导入闲管家，再点击“同步并导入闲管家历史订单”。鱼管家会统一同步、去重并标记待核对，不再上传本地 CSV 或 Excel 订单文件。接口受近六个月更新时间及单次 10000 条限制，数量较多时先在闲管家分批整理。

02 · 配置商品成本与供货商

打开“设置 → 商品与供应商”，按商品类型维护单件成本、默认供货商、微信备注名称和默认发货备注。已有商品规格与成色直接用于辨认，不需要重复编造。

先补齐几笔准备测试的订单成本，再核对利润明细。缺成本订单会单独展示，不会按零成本计入利润。

03 · 生成并核对文字清单

进入“待发货”，勾选订单和对应供货商后导出。核对订单号、商品、规格、数量和收货信息，再复制整份清单或下载 TXT。生成清单不会向平台提交发货。

04 · 设置回款参考，核对利润口径

在“设置 → 统一回款参考规则”调整参考天数，默认发货后 10 天。已完成订单依据平台实际确认时间统计；预计回款不等于账户实际入账。

当前版本的平台费参考为客户实付的 1.6%，逐单四舍五入到分；这不是所有店铺的通用费率，暂未提供通用费率配置界面。若你的规则不同，先反馈或调整实现再依赖利润结果。税费、人工等其他经营支出未自动全部计入。

05 · 备份经营数据

数据库与配置保存在 %LOCALAPPDATA%\XianyuSeller。升级或卸载程序不会主动删除经营数据；迁移电脑时应完整备份并验证恢复。从旧版升级且已有历史视频时，文件继续保留，并可从订单详情只读下载。

遇到问题，先检查哪里？
看到的现象检查与处理
后台打不开从开始菜单重新打开鱼管家，检查 8765 端口是否被其他程序占用；仍失败时查看数据目录中的 logs。
没有同步到订单确认 Key / Secret、店铺授权和同步起始日；到“闲管家 API”查看运行记录并立即同步。
文字清单内容不完整检查商品、规格、数量、供应商和收货资料，重新同步后再次生成。
利润未纳入某些订单检查统计日期依据、订单状态、成本是否齐全，以及记录是否属于经营订单。

第一轮试用，完成这四项就够了。
