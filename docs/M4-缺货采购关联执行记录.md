# M4 缺货采购关联

日期：2026-09-08。

## 已实现流程

已确认的销售订单出现缺口时，点击“为缺货采购”，自动带入对应商品、开单货况和未安排的数量。关联采购的未到数量及已到货可售数量都计入已安排数量，避免重复采购同一缺口。其他日常补货仍从采购页直接创建。

采购单与销售订单双向显示关联。实际收货后，点击“核对货况，为订单备货”，并排查看开单时的货况和本次实物货况，确认后按本次数量锁库存。开单说明保持原样，实际备货的货况、成色和成本另存到销售分配记录；最终出库按这些实际成本计算利润。

订单取消后，采购不会自动取消，详情提示处理；已到货库存保留，不能再为取消订单备货。被订单占用的实物仍不能退回供应商。

## 一致性与验证

完整质量门禁通过：Ruff、格式、类型、Django 检查、迁移一致性及 49 项自动化测试。手机浏览器完成缺货订单 → 创建采购 → 收货 → 核对货况 → 锁定库存，截图检查无横向溢出。

- 创建关联采购锁销售订单及对应库存余额，防止并发重复安排采购。
- 备货按销售订单、库存余额顺序加锁，沿用销售取消和出库的锁顺序。
- 备货要求提交订单版本、实物版本和货况核对确认；校验订单状态、商品对应关系、剩余缺口与可售数量。
- 重复提交返回同一结果；数量、库存、分配、审计和订单事件在同一事务内更新。
- 测试覆盖真实货况备货后出库利润、重复安排采购、并发采购、取消订单、过期实物版本和完整手机浏览器流程。

## 部署与边界

新增 `procurement.0003_purchase_order_item`，在采购单增加可空的销售明细关联；已有采购均保持无关联，不改写库存或历史成本。更新已有环境需运行 `python manage.py migrate`。

当前每张采购单可关联一条销售明细，一条销售明细可有多张采购单；不把采购量自动当成库存，也不自动把到货实物替换原订单货物。供应商直发、销售分批履约及多商品采购仍待后续实现。
