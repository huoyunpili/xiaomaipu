# V1.31 API 字段核验

核验日期：2026-09-15。依据为官方 OpenAPI 导出定义，以及本机已经保存的真实平台快照。本次没有修改真实订单，也没有调用平台发货、退款审批或消息发送接口。

## 1. 官方定义

普通 HTML 页没有展开完整枚举；使用官网 LLM 索引列出的 Markdown OpenAPI 导出可取得 schema：

- [订单详情 OpenAPI](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/api-93586385.md)
- [售后详情 OpenAPI](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/api-472549188.md)

订单枚举为：11 待付款、12 待发货、21 已发货、22 已完成、23 已退款、24 已关闭。原实现把 23 当作已关闭，现已纠正。

退款枚举为：0 未申请、1 等待商家处理、2 等待买家退货、3 等待商家收货、4 退款关闭、5 退款成功、6 已拒绝、8 等待确认退货地址。系统把 1/2/3/8 作为售后进行中；4 回到订单主状态判断；6 提醒人工核对后续责任；未列出的值进入待核对。

官方将 refund_time 说明为退款成功才有值，refund_amount 为累计已退金额。本版只处理全额退款，因此成功代码、有效退款时间、累计退款额与实付相等必须形成一致证据；部分退款、缺少金额或冲突不冒充正常已退款。

refund_type 的 1/2 分别表示仅退款/退货退款；apply_time 是申请时间。收件字段可能仅在待发货时返回，发货后的空收件字段不能覆盖本地已有地址。timeout_type 在 schema 中存在带尾部空格的数字文本，接入层允许去空格后按数字读取，但售后截止时间仍不充当正常订单回款日。

## 2. 真实本地快照交叉核对

使用只读脚本 `scripts/inspect_workspace_states.py`，只输出状态组合、时间字段是否存在、金额是否相等及数量，不输出订单号、姓名、地址、手机号、金额或密钥。

当时共 78 条快照：

| 订单代码 | 数量 | 观察 |
|---|---:|---|
| 11 | 1 | 无付款时间 |
| 12 | 1 | 有付款时间，无发货时间 |
| 21 | 15 | 其中 5 条没有发货时间；2 条退款状态为 3 |
| 22 | 38 | 均有完成时间 |
| 23 | 16 | 其中 13 条退款状态为 5、退款时间存在且退款金额等于实付；其余 3 条未形成完整金额证据 |
| 24 | 7 | 无付款时间 |

这些结果支持实际已完成、全额退款及关闭状态的区分，也证实字段并非每单都完整。不能用这批快照证明全部退款类型都已实测。

## 3. 实现约束与未验证事项

- 售后详情的官方响应未定义 update_time。无版本响应按本次查询观察时间保存，不伪造平台版本；有真实版本的响应通过独立售后记录处理，旧版本不覆盖新状态。
- 订单列表和售后详情均能驱动工作台重新投影。售后详情先确认全额退款时，立即移出担保；不等待供应商追回确认。
- 原来的 refund_status=99 合成样例已改成官方 5；99 单独测试为待核对，不能被测试样例误当作平台枚举。
- 退款关闭、拒绝、待退货和待确认地址的所有真实转移尚未逐一获得当前店铺样例。正常只读同步按官方已知定义处理；未知或矛盾事实保持待核对。
- 售后超时暂停/恢复的真实含义、隐私号能否直接用于供应商履约仍需实单验证。当前不展示未经验证的售后截止日期，不以隐私缺失信息生成有效发货单。
