# 本地发行与数据维护 0.5.0 RC1

## 1. 适用范围

本发行候选面向一名小卖家在自己的 Windows 电脑上运行一个店铺后台。浏览器只是操作界面；关闭浏览器不会停止后台同步、任务和数据库。系统不要求云服务器。

当前已实测环境为 Windows 11、Windows PowerShell 5.1、Docker Desktop Server 29.0.1、Docker Compose 2.40.3。其他系统尚未完成发行验收。首次构建需要联网下载公开镜像和 Python 锁定依赖，建议至少预留 4 GB 内存与 10 GB 磁盘空间；实际经营视频和备份需要另外预留容量。

## 2. 首次安装

1. 安装并启动 Docker Desktop。
2. 在项目根目录打开 Windows PowerShell。
3. 执行：

~~~powershell
./scripts/local_release.ps1 -Action Install
~~~

脚本会在 %LOCALAPPDATA%/XianyuSeller 创建私有经营目录，随机生成 Django 密钥和数据库密码，构建固定版本镜像，迁移数据库并建立默认店铺和渠道。项目没有默认账号或默认密码。

安装完成后访问 http://127.0.0.1:8765。第一次打开会进入“创建店主账号”页面，由使用者自己设置用户名和密码；创建完成后入口自动关闭并进入后台。源代码可以更新或重新下载；经营数据、附件、API 密钥和备份不放在源码目录中。

## 3. 日常管理

~~~powershell
./scripts/local_release.ps1 -Action Start
./scripts/local_release.ps1 -Action Status
./scripts/local_release.ps1 -Action Stop
./scripts/local_release.ps1 -Action Restart
~~~

Start 可以重复运行。Stop 只停止服务，不删除数据库、附件或备份。不要执行 docker compose down -v，也不要手工删除经营目录。

如果使用了自定义数据目录，每个命令都要传入同一个参数：

~~~powershell
./scripts/local_release.ps1 -Action Status -DataDir 'D:/我的小卖铺 数据'
~~~

## 4. 闲管家 API

首次安装后，在经营目录的 config.env 中填写 XGJ_APP_KEY、XGJ_APP_SECRET 和经过核验的 XGJ_BASE_URL，再执行 Restart。真实配置不能提交 Git、放进发行压缩包或发给其他人。

系统继续执行既定边界：API 接入日前的订单由使用者导入；从接入日开始自动同步。未被接口契约和当前授权证明的到账、退款或售后事实保持人工核对，不凭交易状态推断钱款。

## 5. 局域网与手机

先查出电脑的局域网 IPv4 地址，再执行：

~~~powershell
./scripts/local_release.ps1 -Action Configure -BindAddress 0.0.0.0 -PublicUrl http://192.168.1.8:8765
./scripts/local_release.ps1 -Action Restart
~~~

把示例 IP 换成当前电脑地址。手机和电脑必须在可信的同一局域网。只有 Caddy 的 Web 端口映射到主机；PostgreSQL 和 Redis 没有主机端口。允许主机与 CSRF 来源由脚本同步生成。

局域网是明文 HTTP，只适合可信家庭网络。换回仅本机访问：

~~~powershell
./scripts/local_release.ps1 -Action Configure -BindAddress 127.0.0.1 -PublicUrl http://127.0.0.1:8765
./scripts/local_release.ps1 -Action Restart
~~~

## 6. 备份、升级和恢复

手动备份：

~~~powershell
./scripts/local_release.ps1 -Action Backup
~~~

注册每天 03:00 的 Windows 计划任务：

~~~powershell
./scripts/local_release.ps1 -Action ScheduleBackup
~~~

不再需要时可执行 RemoveBackupSchedule。注册和移除计划任务会修改当前 Windows 用户的任务计划，因此没有放进 Install 自动执行。

备份前脚本暂停写入服务并执行钱货对账，导出 PostgreSQL 和私有附件，再把数据库恢复到独立临时库逐表比较行数。只有全部通过才写入 manifest.json 的成功状态。默认超过 24 小时没有成功备份时，下一次 Start 会补做备份。

升级会先备份，再重新构建固定依赖镜像、执行迁移和幂等初始化：

~~~powershell
./scripts/local_release.ps1 -Action Upgrade
~~~

恢复会覆盖当前经营数据，所以必须明确指定当前数据目录 backups 下的一份备份。脚本在覆盖前还会自动保存当前状态：

~~~powershell
./scripts/local_release.ps1 -Action Restore -BackupPath 'C:/Users/你/AppData/Local/XianyuSeller/backups/20260914-120000-a1b2c3' -ConfirmRestore
~~~

数据库 dump 和附件哈希不匹配时拒绝恢复。恢复后再次迁移、钱货对账并等待健康检查。

## 7. 故障处理

- 端口已被占用：先关闭占用程序，或用 Configure -Port 18765 -PublicUrl http://127.0.0.1:18765 改端口。
- Docker 不可用：启动 Docker Desktop，等引擎就绪后重新执行原命令。
- 服务未就绪：执行 Status，再用生成配置查看日志：docker compose --env-file <经营目录>/config.env -f deployment/compose.local.yaml logs --tail 200。
- API 失败：保留人工录入和核对，检查后台“平台同步”的授权和失败原因，不重复创建销售订单。
- 电脑异常关机：重新启动 Docker Desktop 后执行 Start。迁移与初始化可重复，漏掉的周期备份会在启动时补做。

## 8. 版本边界与分发

0.5.0 RC1 已完成本机容器构建、中文和空格数据路径、重复启动、DEBUG=False、内部数据库网络、迁移、钱货对账、手动备份及独立覆盖恢复演练。真实手机上传、全新电脑无缓存安装、Windows 休眠恢复、真实闲管家授权样本和七日经营核对仍需完成，因此当前不是正式版。

打包命令只从干净 Git 提交生成压缩包：

~~~powershell
./scripts/build_release.ps1
~~~

发行清单包含应用源码、迁移、锁文件、Docker 配置、管理脚本、文档和测试；排除实际 .env、config.env、API 密钥、经营数据库、订单附件、日志、备份及 .local-release。公开发布前仍需确定开源许可证和 GitHub 发布目标。
