鱼管家将平台订单事实、本地经营记录和逐单利润放在同一桌面工作台。本文说明已经交付的公版行为、关键数据约束及安装验证范围，可作为排查与后续开发的入口。

架构数据与成本订单同步发货清单安装与修复验证范围开发入口

公开下载：GitHub 最新版本。0.7.3 的安装文件为 FishManager-0.7.3-Windows-Setup.exe。本说明不包含私版试验功能。

1. 本地桌面架构

桌面窗口Electron 展示本地界面，管理启动、托盘及退出。
业务服务内置 Python / Django 处理订单、经营记录、导出和同步任务。
本地存储内置 PostgreSQL 保存结构化数据；配置、附件及备份保存在本机。

发行包内置 Python 3.13.7、PostgreSQL 17.11 和 Electron 44.4.5，无需用户自行安装开发工具或 Docker。内部 Web 与数据库端口由启动流程管理，不能将开发环境端口当作所有安装实例的固定端口。

桌面关闭窗口后仍可在托盘后台运行；彻底退出后停止后台服务。当前标准安装按一个 Windows 用户的一套本地数据使用，尚未交付经过完整验收的双店铺同时运行流程。iOS 客户端、云端托管和跨设备同步不属于本版本。

入口职责
desktop/main.js桌面窗口、启动隔离、托盘与生命周期。
app/desktop/runtime.py读取本地配置，分配服务端口，组织后台运行。
app/integrations/保存平台订单事实、同步记录与接口接入。
app/workbench/经营订单投影、成本快照、发货清单和利润统计。
app/accounts/、app/audit/账号权限及经营操作审计。

2. 数据位置与成本约束

标准安装的数据根目录为 %LOCALAPPDATA%\XianyuSeller，程序目录与经营数据分离。升级或卸载程序不会主动删除经营数据。配置、数据库、备份和历史私有附件需一起保管，不能仅复制程序目录来迁移店铺。

平台订单事实与本地经营订单是不同层次。同步数量不等于经营工作台订单数量；判断是否遗漏时，应以店铺和订单号核对原始记录、投影结果、筛选条件与待核对状态。

默认商品成本与本单成本是两项数据

  • 金额以整数“分”存储。商品默认成本用于成本匹配，本单采用 Trade.unit_cost_fen 成本快照。
  • 未知成本（空值）与明确的 0 元成本不同。0 元属于已知成本，不会自动被新的商品默认价覆盖。
  • 调整商品默认成本不会改写已有非空订单成本快照。历史单成本错误，应通过订单详情填写更正后的单件成本及原因，保存并保留审计记录。
  • 更正成功后输入框清空不表示数据丢失，应核对展示的本单成本、操作记录及统计明细。后续同步不会覆盖已有非空成本快照。

利润统计口径

商品成本 = 数量 × 本单单件成本
平台费参考 = 客户实付 × 1.6%（逐单四舍五入到分）
订单利润 = 客户实付 − 商品成本 − 平台费
演示：200.00 − 150.00 − 3.20 = 46.80 元

每日预计利润按付款日期，时间段实际利润按完成日期。缺成本订单单列，补齐后再纳入相应汇总；全额退款订单不收平台费。运费损失单列。1.6% 是当前程序参考口径，未提供通用费率编辑器，也不代表包含税费、人工、房租等全部经营费用。

3. API 接入与订单同步

在设置内手动填写闲管家 AppKey / AppSecret，保存后验证连接。验证成功后触发同步，应用运行期间按约 5 分钟周期更新。后台完全退出、断网或授权失效都会影响同步，应查看运行记录而非仅依赖页面显示时间。

历史订单先在闲管家准备，再使用“同步并导入闲管家历史订单”。当前列表扫描采用近 179 天更新时间窗口，单次最多 10000 条；更早下单的订单只有在近期更新等条件下才可能返回。按店铺和订单号去重，不通过猜造金额、状态或收货信息补齐未知事实。

平台字段与人工补充需要区分：0.7.2 修复了平台空规格覆盖人工补充的问题。发现来源冲突时保留核对依据，不能以批量覆盖本地经营资料作为修复办法。

4. 公版发货清单

待发货页勾选订单即可导出，供货商筛选可选，未分配供货商也可导出。商品名称、数量与完整收货信息必须可用；平台未提供独立规格时不要求编造，脱敏电话或缺失地址仍不能作为完整发货资料。

导出前重新同步核对，随后生成可复制文字与 TXT。公版不生成供货商远程回填链接，不接收新单号或视频，也不会因生成清单而提交平台发货。旧版已经保存的历史视频保留只读入口。

5. 安装、升级与数据库修复

  1. 使用 64 位 Windows，选择英文程序路径，例如 D:\FishManager。
  2. 安装程序检查 Microsoft VC++ x64 运行库；缺失或版本不足时调用随包提供的微软运行库安装程序。涉及系统组件时可能出现 Windows 授权提示。
  3. 若运行库安装返回需要重启的状态，先重启 Windows 再启动鱼管家，不继续强行初始化数据库。
  4. 准备 PostgreSQL 配置和本地端口，按需初始化、备份、执行数据库迁移，再启动服务。

0.7.2 包含无效端口缓存回退，以及针对安装器所写已知数据库端口配置块的备份和修复。修复范围有限，不任意重写用户数据库配置。正常安装或覆盖升级不需要另跑独立修复工具，也不能保证解决所有外部系统故障。

原生初始化失败时记录 initdb-result.log（含退出码）、initdb-out.log 与 initdb-error.log，失败的临时初始化目录不会当作可用数据库发布。启动失败页可打开诊断文件夹。提交日志前检查并遮去个人路径、客户资料和密钥。

备份前先等待同步结束并从托盘彻底退出。普通用户可完整复制本地数据目录；数据库级维护使用与安装包匹配的 PostgreSQL 工具备份并校验。不要通过清空数据库、重建表或伪造迁移状态处理启动问题。

7. 开发与发布入口

  • scripts/windows_release.ps1：数据库准备、备份、迁移和启动配置。
  • scripts/build_windows_installer.ps1：固定依赖、质量门禁及 Windows 打包。
  • installer/fish-manager.iss、installer/vc-runtime.iss：安装器与运行库前置检查。
  • scripts/build_product_page.py、scripts/build_manual.py、scripts/build_technical_guide.py：构建可独立打开的文档。

按仓库 README 和贡献指南建立隔离开发环境，测试使用演示数据。配置文件、AppSecret、私有附件、数据库备份和真实订单日志不得加入公开仓库。数据库变更先备份，并验证升级与恢复路径；不得以真实店铺发货、退款或发送消息作为普通测试步骤。
