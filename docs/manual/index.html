01 / 使用前先读

普通用户只使用完整安装包

鱼管家定位为鱼小铺后台管理助手，在本地运行，面向单店经营。店主使用电脑管理订单、回款、成本和售后，并按供货商生成可复制或下载的文字清单。

安装方式包含功能需要准备配置和数据位置
Windows 完整安装包经营后台、自动同步、文字发货清单、成本利润与售后跟进64 位 Windows 电脑、网络连接%LOCALAPPDATA%\XianyuSeller

不需要选择基础版或完整协作版，也不需要安装 Docker、Python、uv、Redis、PostgreSQL 或隧道工具。源码与 Docker Compose 只面向开发者，不是普通用户安装步骤。

版本对应：本手册按 0.6.0 正式版编写。下载时请核对安装包版本，预发布版的界面和能力可能不同。

三个账号分别做什么

  • 闲鱼账号：实际卖货的店铺账号，在平台完成店铺授权。
  • 闲管家账号和应用凭据：管理授权店铺，向鱼管家提供接口访问权限。
  • 鱼管家店主账号：首次启动时自己创建，用于登录本机后台。它不是闲鱼密码，也不是 AppSecret。

第一次建议先做只读同步与成本核对，再生成少量文字清单核对内容。鱼管家生成清单不会自动提交平台发货。

02 / 外部服务准备

如何取得闲管家 API 凭据

鱼管家连接的是闲管家开放平台。这里不需要获取闲鱼浏览器 Cookie，也不需要把闲鱼登录密码写入鱼管家。

第 1 步：注册并登录闲管家

打开 闲管家登录页。已有账号直接登录；没有账号时使用其注册入口，按页面要求完成手机号验证。

第 2 步：绑定准备经营的闲鱼店铺

官方手册提供的路径是“销售管理 → 店铺 → 创建闲鱼店铺”，随后进入应用授权。使用目标店铺的闲鱼账号完成授权，回到店铺列表确认店铺身份与授权状态。[闲管家官方操作手册]

第 3 步：确认自研应用接入资格

在闲管家查找“开放平台 / 应用管理 / 我的应用”，进入添加应用，寻找“我有自研系统”一类入口。这里要接入的是自己的经营系统，不是购买虚拟卡券货源。官方材料可确认存在自研接入入口，但不同账号的菜单、资格与套餐可能不同；本手册未登录一个全新账号逐项验收申请页面。

如果没有入口，或要求购买服务，先向闲管家客服确认下面的需求，再决定开通哪一项。不要仅凭普通会员已开通就认为所有 API 都能使用。具体价格、审批资料和有效期以该账号当前开通页面及客服回复为准。

我要将自己的闲鱼实物店铺连接到本地自研经营后台，需要查询授权店铺、订单列表和订单详情。请确认应该开通哪个应用类型及套餐，如何创建自研应用、取得 AppKey / AppSecret，以及是否需要上线或单独授权目标店铺。

入口依据：闲管家官方应用接入图示中可见“我有自研系统”。图示正文服务于其他应用，只用于辨认入口，不照搬其货源配置。鱼管家所用签名凭据以闲管家开放平台接入说明为准。

第 4 步：创建应用、取得凭据并确认生效

  1. 按闲管家当前页面填写应用名称等资料，例如“鱼管家自用”，选择适用于订单查询的自研接入。
  2. 进入应用详情，找到该应用的 AppKey 和 AppSecret。Key 是应用标识，Secret 是应用密钥。
  3. 如果页面要求启用、上线或授权店铺，完成对应步骤。确认目标店铺位于这组应用凭据允许访问的范围内。
  4. 把凭据只保存到自己的本机配置文件。不要在公开反馈、宣传截图或 GitHub 中粘贴它们。
接口回调地址怎么填？当前鱼管家通过后台任务主动查询订单，不依赖订单 Webhook 接收地址。若应用创建页面强制要求回调地址，请让闲管家确认轮询接入方式或联系维护者，不要虚构地址。

第 5 步：列出必须能够完成的接口动作

用途应该能做到验证方式
连接店铺查询授权店铺鱼管家“验证授权店铺”成功，身份匹配
同步订单查询订单列表及详情立即同步成功，看到已知订单

“拿到 Key”不等于“接口权限齐全”。至少用一笔已知订单核对店铺身份、金额、状态和商品信息。

03 / 安装

下载一个安装包，双击完成

  1. 从 GitHub Releases 下载 鱼管家-0.6.0-安装程序.exe。
  2. 双击安装，等待内置数据库和服务初始化。安装过程会自动配置完整经营后台。
  3. 浏览器自动打开 http://127.0.0.1:8765 后，创建自己的店主账号；没有默认账号密码。
成功标志：能看到首次创建账号页面；从开始菜单再次打开“鱼管家”也能进入同一地址。

以后登录 Windows 时鱼管家自动启动。程序升级或卸载不会主动删除 %LOCALAPPDATA%\XianyuSeller 中的订单、旧版视频、配置和备份。

正式版不提供公网入口，也不需要隧道或中继。店主在本机复制或下载文字清单，再通过自己常用的聊天工具发送给供货商。
05 / 首次连接

连接店铺，确认同步真的成功

入口：设置 → 闲管家 API。

  1. 点击“验证授权店铺”。若出现权限或配置错误，先核对 Key、Secret、应用状态和店铺授权。
  2. 查看页面显示的同步边界。首次建立连接会记录接入日期；旧实例如果缺少可信日期，会要求确认。
  3. 点击“立即同步”，稍后刷新或查看运行记录，确认任务已完成。
  4. 比对一笔平台待发货订单的订单号、实付、状态和商品信息。
  5. 需要持续更新时点击“开启每 5 分钟同步”。浏览器关闭不影响后台任务，电脑或服务停止会影响同步。

“重扫接入日起订单”用于补查当前经营范围；接入前订单先导入闲管家，再按历史订单同步操作。

应同时看到“最近完整同步”更新、运行记录成功，以及一笔已知订单内容匹配。只有页面能打开或任务已发出，还不能算同步完成。

当前以单店为主要使用方式。凭据下有多家店铺时，务必核对实际连接的是哪一家；店铺不符时停止导出与发货，联系维护者确认，不能把当前安装当作多店切换后台。

06 / 工作台

每天先看待办，再看资金安排

区域含义建议操作
待发货需要继续安排发出的订单进入待发货，核对商品与供货商
担保中金额按本地订单状态推算的未完成资金点击进入构成明细；不当作平台钱包可提现余额
退款处理中尚未完成客户退款的售后进入退款售后，跟进平台处理
今日预计利润按付款日期及已有成本统计查看缺成本提示并补充

回款数字怎么理解

  • 今日已完成：今天平台确认收货／完成的订单实付金额。
  • 今日剩余预计：依据发货时间和参考天数估算，尚未完成的订单金额；与已完成部分不重复计算。
  • 今日合计：上述两部分之和。
  • 未来三天：从明天起，预计在随后三天完成的未完成订单。

默认参考日期为发货后 10 × 24 小时。退款中的订单暂停参考；缺少可信发货时间的记录不能硬推日期。平台扣费后的真实到账金额与入账日期，以资金账单为准。实际业务当天没有对应订单时，显示 0 是正常结果，宣传演示数字不作为经营目标。

清单变化提醒

发现最新清单中的订单有变化时，先核对是否退款、改派或已发货，再与供货商确认后重新导出。旧清单保留为历史记录，不应继续作为当前发货依据。

07 / 成本与供应商

先认准商品，再填成本

入口：设置 → 商品与供应商，或订单列表右上角“商品成本与供应商”。

  1. 核对商品图片、名称、规格和已有成色。必要时点击“查看关联订单”。
  2. 参考最近成交售价帮助辨认；售价是销售金额，不是采购成本。
  3. 填写单件成本，单位为元，数量由订单确定。
  4. 选择或输入默认供应商；需要时填写供应商微信备注名称和默认发货备注。
  5. 保存该商品配置，回订单或利润页面检查效果。
字段填写示例用途
单件成本150.00两件对应 300 元商品成本，不在这里填写两件合计
默认供应商数码优选（示例）分组生成发货清单；同一家尽量保持名称一致
微信备注名称数码优选售后（示例）帮助店主识别联系人，不会自动发微信
发货备注核对颜色、配件，发货前拍视频用于后续清单沟通

商品成本变更不会直接改写已有订单成本快照。历史某一单成本错了，应进入订单详情，填写“更正本单单件成本”和原因，再保存；不要为改一单而批量重写全部商品价格。

07 / 发货清单

把正确的文字清单交给正确的供货商

入口：左侧“待发货”。该页保持简洁；复杂检索可到“全部订单”。

  1. 逐单检查商品、规格、数量、供货商以及收货信息是否完整。
  2. 勾选准备处理的订单。“全选本页”只选择当前页，不等于所有分页。
  3. 在“导出给哪些供货商”中勾选本次需要的供货商，支持多选，默认不选。
  4. 点击“导出发货单”。系统先同步核对，期间稍等，不重复点击。
  5. 在“清单已生成”页点击“复制整份清单”或“下载 TXT”。
  6. 通过自己的聊天工具，只把对应文字清单发给该供货商。

清单中包含订单号、商品、已有规格、数量、收货人、电话、地址和备注。正式版不生成公网链接，不接收供货商回填单号或上传视频，也不会因为生成清单而自动向平台提交发货。

页面底部“历史导出批次”可找回以前的清单。旧清单已经提示变化时，应以当前订单和重新导出的清单为准。

08 / 订单跟进

待完成、全部订单与订单详情

待完成：发出后继续跟进

在“待完成”查看尚未完成交易的订单。可按等待时间或参考回款日排序，结合搜索、供应商和日期筛选跟进。找不到记录时，先清除筛选，再到“全部订单”按订单号找。

全部订单：检索与核对的入口

  1. 使用状态标签选择待发货、待完成、已完成、售后或其他分类。
  2. 搜索订单号、型号或收件人；按需要选择供货商。
  3. 选择日期依据：下单、付款或完成日期。核对本月成交应使用完成日期。
  4. 点击“查询”，需要重新开始时“清除筛选”；可导出当前范围订单 CSV。

订单详情：补充本单经营信息

点击订单卡片“查看 / 补充”，核对平台时间、物流、退款进度和计算过程。可补充本单供应商、收货信息、发货备注、退货单号、售后备注、实际退货运费损失等，按页面需要填写后保存。

详情页“保存”只修改本地经营资料，不会把地址、备注、单号或退款状态自动写回平台。平台操作应在平台或获得授权的工具中完成，再回鱼管家同步核对。

从旧版升级且曾收到供货商视频时，订单详情会保留只读下载入口；正式版不会新增这类记录。“待核对”说明数据或状态无法可靠判定，不表示缺少商品成本。

11 / 售后

客户退款与供货商退钱，分别登记

入口：左侧“退款售后”。

标签显示范围
退款处理中平台尚未完成客户退款的订单
供应商待追回退货退款中供货商货款尚未追回的订单，可包含客户退款处理中或已退款
客户退款已完成平台确认客户退款成功的订单，无论供货商的钱是否已收回
查看全部售后包含已经登记追回的历史记录
  1. 先在平台处理客户售后，鱼管家用来跟进进度与经营记录。
  2. 与供货商核实退货和采购款返还情况；不要把买家退货签收当作自己已经收到钱。
  3. 收到供货商货款后，在对应订单下拉选择“已追回”，点击“确定”。
  4. 确认文字变绿；默认待追回列表中，该订单会移出，可在全部售后找回。
  5. 如果误点，找到原订单改回“未追回”并确认。真实发生退货运费损失时，进入详情按元填写。

待追回金额依赖商品成本。缺成本时先补齐，不能把未知当作零。当前是“未追回 / 已追回”登记，尚不提供完整的部分追回金额流水；只收到部分款项时不要标为全部追回，可先用售后备注记录并继续跟进。

退款清单可以按现有导出入口交给供货商核对；它与待发货的文字清单不同，当前仍可能提供图片形式。

12 / 经营核算

怎样查看、解释并核对利润

入口：左侧“利润统计”。

  1. 选择“每日预计利润”或“时间段实际利润”。预计按付款日期，实际按成交完成日期。
  2. 选择今天、本月、上月或自定义范围，必要时设置排序并点击“查询”。
  3. 先看纳入订单数与缺少成本订单数，再看销售额、成本、费用和利润。
  4. 到“逐单计算”点击金额，展开实付、成本及费用的来源。
  5. 补齐缺成本订单或更正错误成本后重新核对；需要留档时导出当前统计明细。
商品成本 = 数量 × 本单单件成本快照
当前平台费参考 = 客户实付 × 1.6%（逐单四舍五入到分）
订单利润 = 客户实付 − 商品成本 − 平台费

示例：200.00 − 150.00 − 3.20 = 46.80 元

运费损失单列，不直接混入上述成交利润公式。该公式不包含全部税费、人工、房租等支出。当前 1.6% 是程序的计算口径，不是通用店铺实际费率；不同费率或历史费率应先核对，界面暂未提供通用费率编辑器。

为什么某月初订单没算进来

按顺序检查：平台是否已经完成交易 → 完成日期是否落在所选月 → 本地是否已同步或导入 → 是否缺成本 → 是否属于非经营或待核对记录。付款在月初但下月完成的订单，会在下月实际利润中出现。不要仅凭下单日期判断漏算。

13 / 历史资料

从闲管家同步历史订单

入口：设置 → 闲管家 API → 同步并导入闲管家历史订单。鱼管家不再接收本地 CSV 或 Excel 订单文件，避免两套导入口径产生重复、状态不一致和字段缺失。

  1. 先在闲管家完成历史订单导入，并确认订单号、金额、状态和时间正确。
  2. 回到鱼管家点击“同步并导入闲管家历史订单”。已有订单按店铺和订单号去重，不会重复创建。
  3. 稍后刷新同步页面，在运行记录中查看扫描数量、历史数量和已导入历史数量。
  4. 到“全部订单”按订单号抽查；缺成本、字段冲突或平台信息不足的订单会保留为待核对，不会猜造数据。

闲管家订单列表接口按更新时间查询，当前只能扫描近 179 天并且单次最多 10000 条。较早订单只有在导入闲管家后产生了近期更新时间时才可能返回；数量过多时先在闲管家分批整理再重试。

顶部显示当前登录用户，优先显示“你的称呼”，未填写时用用户名；账号菜单可进入设置和退出。

忘记密码且无法登录时，当前没有面向公众的邮箱自助找回流程。由有权维护本机的人协助，通过对应部署环境的 Django 管理命令重设指定账号密码；不要重新初始化数据库。

13 / 日常维护

启停、备份、升级与迁到家用电脑

启动与停止

从开始菜单选择“鱼管家”启动并打开页面，选择“停止鱼管家”安全停止后台。Windows 登录时会自动启动；无须先启动数据库或其他组件。

升级

先完成备份，再双击新版安装程序覆盖安装。安装器只更新程序文件，不主动删除 %LOCALAPPDATA%\XianyuSeller 中的经营数据，并会自动执行必要的数据结构升级。

当前备份办法

  1. 暂停编辑并等待正在运行的同步完成。
  2. 从开始菜单选择“停止鱼管家”。
  3. 按 Win+R 打开 %LOCALAPPDATA%，把整个 XianyuSeller 文件夹复制到另一块磁盘。
  4. 重新打开鱼管家，并抽查订单、设置和历史数据。

安装包的一键备份与恢复界面仍待补齐；在它通过恢复验收前，不把“复制了某个数据库文件”宣传成已验证备份。迁移或恢复应由维护人员在副本上验证后再切换。

迁移到家用电脑：验收顺序

  1. 记录原部署路径、版本和数据位置，完整备份数据库、私有文件和配置。
  2. 在新电脑安装相同版本，由对应恢复流程恢复；只复制 HTML 或源码不够。
  3. 确认历史订单数量和关键金额；从旧版升级且有历史视频时，抽查一次只读下载。
  4. 验证 API 店铺身份、执行一次只读同步，再启用自动同步。
  5. 确认新环境正常后，停用旧环境自动同步，避免两台电脑并行处理。
  6. 配置合适的开机启动、关闭自动睡眠，并实际重启验证恢复能力。
16 / 故障排查

从现象找到下一步

现象按顺序检查怎样确认恢复
8765 打不开从开始菜单重新打开鱼管家 → 检查 8765 端口是否被占用 → 查看数据目录 logs登录页或工作台可打开；不要只靠“进程存在”判断
API 验证失败是否修改了对应部署的正确配置文件 → 是否重启 → Key/Secret 是否匹配 → 应用和店铺授权是否有效验证显示正确店铺，立即同步得到已知订单
错误 100001该错误不能单独锁定原因。结合提示检查应用权限、店铺授权、套餐，以及发货参数和默认寄件地址相应动作真实成功；不要仅换一个地址反复试写
同步任务迟迟不完成重新打开鱼管家，查看最近运行记录与数据目录中的 worker / beat 日志完整同步时间更新，记录完成
订单比闲管家少清除筛选 → 全部订单按号找 → 核对连接店铺 → 查看同步运行记录 → 对历史订单执行“同步并导入闲管家历史订单”目标订单可找到，运行记录显示扫描及导入数量
回款为零或日期不对核对统计范围、平台完成时间、可信发货时间、退款状态与参考天数合计能逐笔对到明细；不手改金额凑数
利润少算核对完成日期、成本、导入来源、非经营与待核对状态纳入订单和排除原因都能解释
图片没有显示网络与图片缓存 → 订单来源是否有图片 → 平台是否实际返回图片有来源图片的订单能显示；无来源时不会凭空补造
文字清单内容不完整订单商品、规格、数量、供应商和收货信息是否完整 → 是否重新同步后再次生成复制或下载的 TXT 与当前订单内容一致
上传失败单文件是否超过 60MB、是否超过 10 个、磁盘是否有空间、网络和链接是否有效出现已保存状态，店主可下载原视频
