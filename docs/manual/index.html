01 / 使用前先读

先选择适合自己的安装路径

鱼管家定位为鱼小铺后台管理助手，在本地运行，面向单店经营。店主使用电脑管理订单、回款、成本和售后；启用公网入口后，供货商可通过手机浏览器回传单号与视频。

路径适合的用途需要准备配置和数据位置
A · Docker 发行方式先使用经营后台；不自动部署供货商公网守护Windows、Docker Desktop、完整源码%LOCALAPPDATA%\XianyuSeller；配置为 config.env
B · Windows 源码方式测试完整的供货商发货与本地视频流程Windows、Python 3.12/3.13、uv、Docker Desktop；公网需要 cloudflared项目根目录 .env.local；私有文件默认在 .local\private-media

两条路径只选一条开始。不要同时运行并占用 8765 端口。A 的数据不会自动出现在 B 中，反过来也一样；已有订单时切换路径，需要先备份和迁移。

版本对应：本手册按 2026-09-18 当前工作区编写，公开仓库可能暂未包含全部最新改动。Excel 收入账单直接导入、六项本地寄件人配置、顶部账号菜单属于近期更新；如下载版本没有这些入口，请先核对所用源码版本。历史 CSV 导入、平台默认寄件地址、设置中的“我的账号”可用于对应旧版。不能仅凭同为 RC1 就认定功能完全一致。

三个账号分别做什么

  • 闲鱼账号：实际卖货的店铺账号，在平台完成店铺授权。
  • 闲管家账号和应用凭据：管理授权店铺，向鱼管家提供接口访问权限。
  • 鱼管家店主账号：首次启动时自己创建，用于登录本机后台。它不是闲鱼密码，也不是 AppSecret。

第一次建议先做只读同步与成本核对。确认商品确实准备发出后，再用真实订单和真实快递单号完成第一次平台发货。

02 / 外部服务准备

如何取得闲管家 API 凭据

鱼管家连接的是闲管家开放平台。这里不需要获取闲鱼浏览器 Cookie，也不需要把闲鱼登录密码写入鱼管家。

第 1 步：注册并登录闲管家

打开 闲管家登录页。已有账号直接登录；没有账号时使用其注册入口，按页面要求完成手机号验证。

第 2 步：绑定准备经营的闲鱼店铺

官方手册提供的路径是“销售管理 → 店铺 → 创建闲鱼店铺”，随后进入应用授权。使用目标店铺的闲鱼账号完成授权，回到店铺列表确认店铺身份与授权状态。[闲管家官方操作手册]

第 3 步：确认自研应用接入资格

在闲管家查找“开放平台 / 应用管理 / 我的应用”，进入添加应用，寻找“我有自研系统”一类入口。这里要接入的是自己的经营系统，不是购买虚拟卡券货源。官方材料可确认存在自研接入入口，但不同账号的菜单、资格与套餐可能不同；本手册未登录一个全新账号逐项验收申请页面。

如果没有入口，或要求购买服务，先向闲管家客服确认下面的需求，再决定开通哪一项。不要仅凭普通会员已开通就认为所有 API 都能使用。具体价格、审批资料和有效期以该账号当前开通页面及客服回复为准。

我要将自己的闲鱼实物店铺连接到本地自研经营后台，需要查询授权店铺、查询订单列表和详情、查询快递公司、提交物流发货。请确认应该开通哪个应用类型及套餐，如何创建自研应用、取得 AppKey / AppSecret，以及是否需要上线或单独授权目标店铺。

入口依据：闲管家官方应用接入图示中可见“我有自研系统”。图示正文服务于其他应用，只用于辨认入口，不照搬其货源配置。鱼管家所用签名凭据以闲管家开放平台接入说明为准。

第 4 步：创建应用、取得凭据并确认生效

  1. 按闲管家当前页面填写应用名称等资料，例如“鱼管家自用”。选择适用于订单管理与物流发货的自研接入。
  2. 进入应用详情，找到该应用的 AppKey 和 AppSecret。Key 是应用标识，Secret 是应用密钥。
  3. 如果页面要求启用、上线或授权店铺，完成对应步骤。确认目标店铺位于这组应用凭据允许访问的范围内。
  4. 把凭据只保存到自己的本机配置文件。不要在公开反馈、宣传截图或 GitHub 中粘贴它们。
接口回调地址怎么填？当前鱼管家通过后台任务主动查询订单，不依赖订单 Webhook 接收地址。不要把供货商上传网址当作订单推送回调地址。若应用创建页面强制要求回调地址，请让闲管家确认轮询接入方式或联系维护者，不要虚构地址。

第 5 步：列出必须能够完成的接口动作

用途应该能做到验证方式
连接店铺查询授权店铺鱼管家“验证授权店铺”成功，身份匹配
同步订单查询订单列表及详情立即同步成功，看到已知订单
识别并提交物流查询快递公司；物流发货用一笔真实可发货订单提交后，在平台核对单号与状态

“拿到 Key”不等于“接口权限齐全”，“能查订单”也不等于“能发货”。真实写入验证放在环境和寄件地址配置完成之后。

03 / 安装路径 A

Docker 方式：先把经营后台用起来

准备软件与目录

  1. 从 Docker 官方页面安装并启动 Docker Desktop。按安装器提示启用它需要的系统组件。
  2. 打开项目仓库，选择 Code → Download ZIP，解压完整项目；不要只下载某个脚本。
  3. 进入能看到 manage.py、scripts、deployment 的文件夹，在此打开 PowerShell。
docker version
docker compose version
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Install

前两条用于检查 Docker 可用；若提示无法连接 Docker 引擎，先启动 Docker Desktop，再重试。安装脚本会构建环境、生成本地配置并初始化服务。

成功标志：脚本完成后访问 http://127.0.0.1:8765，看到首次创建店主账号页面。创建自己的用户名与密码，没有默认账号密码。

写入 API 配置

按 Win+R，输入 %LOCALAPPDATA%\XianyuSeller 打开数据目录。用文本编辑器打开已有的 config.env，修改或补充以下三项，保留其他设置：

XGJ_APP_KEY=你的应用Key
XGJ_APP_SECRET=你的应用Secret
XGJ_BASE_URL=https://open.goofish.pro

等号右侧替换为真实值，不保留“你的应用Key”这样的提示文字。不要把文件存成 config.env.txt，不要替换脚本已经生成的数据库密码与 Django 密钥。

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Restart

重启后继续阅读连接店铺与同步。

自定义数据位置或端口

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Install -DataDir 'D:/我的小卖铺数据' -Port 8766

这只是首次安装示例。使用自定义目录后，每次管理操作都应带上相同的 -DataDir，访问地址使用实际端口。不要把经营数据目录设成源码目录或磁盘根目录。

A 路径当前没有自动部署供货商公网上传守护；也尚未在 Docker 编排中传入六项 XGJ_SHIP_* 寄件人配置。完整供货商协作请使用 B 路径，寄件地址优先在闲管家设为默认。仅向 A 的 config.env 添加六个字段不会自动让容器读取它们。
04 / 安装路径 B

Windows 源码方式：启用完整供货商协作

第 1 步：准备工具

安装 Python 3.12 或 3.13、uv、Docker Desktop。下载完整项目，在项目根目录打开 PowerShell，检查：

python --version
uv --version
docker compose version

命令不存在时，按对应官方安装说明补齐并重新打开 PowerShell。执行下面的初始化命令前，确保 A 路径未占用同一服务端口。

第 2 步：初始化依赖与数据库

uv sync --frozen
docker compose -f deployment/compose.yaml up -d --wait
uv run python manage.py migrate
uv run python manage.py bootstrap

依次确认每条命令成功，再继续下一条。bootstrap 初始化基础业务配置，不是生成一个供所有人共用的默认登录密码。

第 3 步：填写本机配置

把根目录 .env.example 复制一份，重命名为 .env.local。文件资源管理器开启“显示文件扩展名”，确认末尾没有 .txt。已有该文件时直接编辑，不要覆盖。

XGJ_APP_KEY=你的应用Key
XGJ_APP_SECRET=你的应用Secret
XGJ_BASE_URL=https://open.goofish.pro

保留示例中的数据库和 Redis 本地配置，除非维护人员已经调整对应服务。不要把 A 的 config.env 整份替换过来，两种部署的连接方式不同。

第 4 步：启动并创建店主账号

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1

访问 http://127.0.0.1:8765 并创建账号。该脚本启动后台页面、任务处理进程和周期调度，随后尝试启动供货商守护；尚未安装 cloudflared 时，公网入口仍需完成下一步。

修改本地配置后，用下面命令使后台及任务进程重新读取：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1 -Restart

第 5 步：配置寄件地址

先在闲管家地址管理中填写有效寄件人、手机号和地址，设置为默认发货地址。也可在支持该功能的 B 路径源码中，把下面六项全部写入 .env.local：

XGJ_SHIP_NAME=实际寄件人
XGJ_SHIP_MOBILE=实际手机号
XGJ_SHIP_PROV_NAME=省级名称
XGJ_SHIP_CITY_NAME=市级名称
XGJ_SHIP_AREA_NAME=区县名称
XGJ_SHIP_ADDRESS=详细寄件地址

六项全留空时使用平台默认地址；选择本地配置时六项应完整且真实，填写完重启。多供货商各自配置独立寄件地址尚未实现。

第 6 步：开启供货商公网入口

  1. 从 Cloudflare 官方发布页下载匹配 Windows 架构的可执行文件。
  2. 在项目中创建 .local\tools 文件夹，把文件命名为 cloudflared.exe 并放入其中。
  3. 运行以下命令：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_supplier.ps1

当前公网地址保存在 .local\supplier-runtime.json，同时由守护写入后台配置。导出发货清单后应出现供货商入口。用手机移动网络打开一次，确认公网真实可达。

成功标志：外网手机能看到该清单订单及收货信息，上传一段真实属于测试订单的合法视频后，后台订单详情能下载到同一原文件。平台发货另行使用准备好的真实包裹验证。
电脑开机、联网、不休眠，且数据库、后台任务、上传网关和隧道都运行，供货商才能持续使用。临时入口无固定有效时长承诺；隧道重建会产生新网址，必须重新发送当前链接。不要把 8765 管理后台直接作为公网隧道目标。
05 / 首次连接

连接店铺，确认同步真的成功

入口：设置 → 闲管家 API。

  1. 点击“验证授权店铺”。若出现权限或配置错误，先核对 Key、Secret、应用状态和店铺授权。
  2. 查看页面显示的同步边界。首次建立连接会记录接入日期；旧实例如果缺少可信日期，会要求确认。起始日固定后，不通过反复更改日期来尝试获取历史。
  3. 点击“立即同步”，稍后刷新或查看运行记录，确认任务已完成。
  4. 比对一笔平台待发货订单的订单号、实付、状态和商品信息。
  5. 需要持续更新时点击“开启每 5 分钟同步”。浏览器关闭不影响后台任务，电脑或服务停止会影响同步。

“重扫接入日起订单”用于补查当前同步范围内的记录，不意味着平台一定返回绑定前全部历史订单。历史资料按历史导入处理。

应同时看到“最近完整同步”更新、运行记录成功，以及一笔已知订单内容匹配。只有页面能打开或任务已发出，还不能算同步完成。

当前以单店为主要使用方式。凭据下有多家店铺时，务必核对实际连接的是哪一家；店铺不符时停止导出与发货，联系维护者确认，不能把当前安装当作多店切换后台。

06 / 工作台

每天先看待办，再看资金安排

区域含义建议操作
待发货需要继续安排发出的订单进入待发货，核对商品与供货商
担保中金额按本地订单状态推算的未完成资金点击进入构成明细；不当作平台钱包可提现余额
退款处理中尚未完成客户退款的售后进入退款售后，跟进平台处理
今日预计利润按付款日期及已有成本统计查看缺成本提示并补充

回款数字怎么理解

  • 今日已完成：今天平台确认收货／完成的订单实付金额。
  • 今日剩余预计：依据发货时间和参考天数估算，尚未完成的订单金额；与已完成部分不重复计算。
  • 今日合计：上述两部分之和。
  • 未来三天：从明天起，预计在随后三天完成的未完成订单。

默认参考日期为发货后 10 × 24 小时。退款中的订单暂停参考；缺少可信发货时间的记录不能硬推日期。平台扣费后的真实到账金额与入账日期，以资金账单为准。实际业务当天没有对应订单时，显示 0 是正常结果，宣传演示数字不作为经营目标。

清单变化提醒

发现最新清单中的订单有变化时，先核对是否退款、改派或已发货，再与供货商确认后重新导出。旧清单保留为历史记录，不应继续作为当前发货依据。

07 / 成本与供应商

先认准商品，再填成本

入口：设置 → 商品与供应商，或订单列表右上角“商品成本与供应商”。

  1. 核对商品图片、名称、规格和已有成色。必要时点击“查看关联订单”。
  2. 参考最近成交售价帮助辨认；售价是销售金额，不是采购成本。
  3. 填写单件成本，单位为元，数量由订单确定。
  4. 选择或输入默认供应商；需要时填写供应商微信备注名称和默认发货备注。
  5. 保存该商品配置，回订单或利润页面检查效果。
字段填写示例用途
单件成本150.00两件对应 300 元商品成本，不在这里填写两件合计
默认供应商数码优选（示例）分组生成发货清单；同一家尽量保持名称一致
微信备注名称数码优选售后（示例）帮助店主识别联系人，不会自动发微信
发货备注核对颜色、配件，发货前拍视频用于后续清单沟通

商品成本变更不会直接改写已有订单成本快照。历史某一单成本错了，应进入订单详情，填写“更正本单单件成本”和原因，再保存；不要为改一单而批量重写全部商品价格。

08 / 发货清单

把正确的订单交给正确的供货商

入口：左侧“待发货”。该页保持简洁；复杂检索可到“全部订单”。

  1. 逐单检查商品、规格、数量、供货商以及收货信息是否完整。
  2. 勾选准备处理的订单。“全选本页”只选择当前页，不等于所有分页。
  3. 在“导出给哪些供货商”中勾选本次需要的供货商，支持多选，默认不选。
  4. 点击“导出发货单”。系统先同步核对，期间稍等，不重复点击。
  5. 在“清单已生成”页分别打开供货商清单，点击“复制整份清单”或“下载 TXT”。
  6. 只把对应清单及专属链接发给该供货商。

清单中包含商品、已有规格、数量、收货人、电话、地址和备注。生成清单不会自动向供货商发微信，也不会仅因导出就把平台改为已发货。

清单链接的管理

  • 没有公网入口时，文字清单可能没有外网上传链接；先完成 B 路径配置。
  • 专属链接是访问凭证，持有者可以操作该范围订单；它不验证对方本人身份。
  • 链接默认 30 天到期，可在清单页“停用此链接”。停用后要继续使用，应重新导出。
  • 链接发错对象时立即停用并重新导出；不要只删除聊天消息就认为失效。
  • 临时隧道网址变化后，重新进入清单复制最新链接并通知供货商。

页面底部“历史导出批次”可找回以前的清单。旧清单已经提示变化时，应以当前订单和重新导出的清单为准。

09 / 可直接发给供货商的操作说明

供货商：填单号、交视频，分次完成

准备：店主发送的专属链接、真实包裹快递单号、该订单的发货前视频。供货商不需要店主的后台账号。

  1. 打开链接，按商品、规格、数量及收件人辨认订单，点击“复制收货信息”。
  2. 确认包裹与订单对应，输入真实快递单号。系统按本地规则识别常见快递；识别错误或未识别时手动选择。
  3. 核对无误后点击“保存单号并提交发货”。这个按钮会向平台提交发货，不是只存草稿。
  4. 等待页面显示结果。提示待处理或待确认时，先联系店主核对，不要反复换单号提交。
  5. 在同一订单选择发货前视频，点击“保存所选视频”。等待服务端确认已保存。
  6. 可以退出后再打开原链接补传其他订单或剩余视频；已成功保存的内容保留。
每个视频最多 60 MB，每单最多 10 个。中断或失败时重试失败项；同内容重复上传会去重。只有页面明确显示保存成功，才算已经交到店主电脑。

店主怎样找到视频

全部订单 → 搜索订单 → 查看 / 补充 → “供货商发货回传 / 本地发货视频”。点击原文件名下载，可以看到保存时间、大小与 SHA-256 校验值。磁盘默认位置为 .local\private-media\supplier-evidence\订单UUID\；UUID 不是平台订单号，因此优先从系统按订单检索。

视频留存方便整理证据，不保证纠纷结果。供货商入口不提供其他供货商订单、商品成本或管理后台访问。

10 / 订单跟进

待完成、全部订单与订单详情

待完成：发出后继续跟进

在“待完成”查看尚未完成交易的订单。可按等待时间或参考回款日排序，结合搜索、供应商和日期筛选跟进。找不到记录时，先清除筛选，再到“全部订单”按订单号找。

全部订单：检索与核对的入口

  1. 使用状态标签选择待发货、待完成、已完成、售后或其他分类。
  2. 搜索订单号、型号或收件人；按需要选择供货商。
  3. 选择日期依据：下单、付款或完成日期。核对本月成交应使用完成日期。
  4. 点击“查询”，需要重新开始时“清除筛选”；可导出当前范围订单 CSV。

订单详情：补充本单经营信息

点击订单卡片“查看 / 补充”，核对平台时间、物流、退款进度和计算过程。可补充本单供应商、收货信息、发货备注、退货单号、售后备注、实际退货运费损失等，按页面需要填写后保存。

详情页“保存”主要修改本地经营资料，不等于把地址、备注或退款状态自动写回闲鱼。只有明确标注“提交发货”的流程会执行对应平台发货操作。平台地址变更应在平台完成，并重新同步核对。

“待核对”说明数据或状态无法可靠判定，不表示缺少商品成本。阅读订单上的具体原因，与平台对照；不要为消除提示而编造完成时间或退款金额。

11 / 售后

客户退款与供货商退钱，分别登记

入口：左侧“退款售后”。

标签显示范围
退款处理中平台尚未完成客户退款的订单
供应商待追回退货退款中供货商货款尚未追回的订单，可包含客户退款处理中或已退款
客户退款已完成平台确认客户退款成功的订单，无论供货商的钱是否已收回
查看全部售后包含已经登记追回的历史记录
  1. 先在平台处理客户售后，鱼管家用来跟进进度与经营记录。
  2. 与供货商核实退货和采购款返还情况；不要把买家退货签收当作自己已经收到钱。
  3. 收到供货商货款后，在对应订单下拉选择“已追回”，点击“确定”。
  4. 确认文字变绿；默认待追回列表中，该订单会移出，可在全部售后找回。
  5. 如果误点，找到原订单改回“未追回”并确认。真实发生退货运费损失时，进入详情按元填写。

待追回金额依赖商品成本。缺成本时先补齐，不能把未知当作零。当前是“未追回 / 已追回”登记，尚不提供完整的部分追回金额流水；只收到部分款项时不要标为全部追回，可先用售后备注记录并继续跟进。

退款清单可以按现有导出入口交给供货商核对；它与待发货的文字清单不同，当前仍可能提供图片形式。

12 / 经营核算

怎样查看、解释并核对利润

入口：左侧“利润统计”。

  1. 选择“每日预计利润”或“时间段实际利润”。预计按付款日期，实际按成交完成日期。
  2. 选择今天、本月、上月或自定义范围，必要时设置排序并点击“查询”。
  3. 先看纳入订单数与缺少成本订单数，再看销售额、成本、费用和利润。
  4. 到“逐单计算”点击金额，展开实付、成本及费用的来源。
  5. 补齐缺成本订单或更正错误成本后重新核对；需要留档时导出当前统计明细。
商品成本 = 数量 × 本单单件成本快照
当前平台费参考 = 客户实付 × 1.6%（逐单四舍五入到分）
订单利润 = 客户实付 − 商品成本 − 平台费

示例：200.00 − 150.00 − 3.20 = 46.80 元

运费损失单列，不直接混入上述成交利润公式。该公式不包含全部税费、人工、房租等支出。当前 1.6% 是程序的计算口径，不是通用店铺实际费率；不同费率或历史费率应先核对，界面暂未提供通用费率编辑器。

为什么某月初订单没算进来

按顺序检查：平台是否已经完成交易 → 完成日期是否落在所选月 → 本地是否已同步或导入 → 是否缺成本 → 是否属于非经营或待核对记录。付款在月初但下月完成的订单，会在下月实际利润中出现。不要仅凭下单日期判断漏算。

13 / 历史资料

导入接入之前的订单

入口：设置 → 历史订单导入。导入前先备份，建议先用少量已知记录验证字段与金额。

方式一：按 CSV 模板导入

  1. 点击“下载 CSV 模板”，以下载文件的表头为准。
  2. 保留订单号为文本，避免 Excel 把长数字变成科学计数法或丢失尾数。
  3. 日期使用北京时间，例如 2026-09-01 14:00:00；金额单位是元。
  4. 商品标识使用闲管家 product_id，规格与已有商品一致；需要区分 SKU 时使用模板中的可选“规格标识”。
  5. 填写模板支持的状态，不随意新建状态名称。上传后查看成功、跳过和错误提示。

重复订单会跳过，不覆盖现有记录；格式错误需修正再导入。把成本填错后重复导入同一订单，不能作为覆盖成本的办法。

方式二：鱼小铺“账单明细收入”Excel

近期更新支持直接选择该类型 .xlsx 文件。它不是任意 Excel 通用导入器；如果安装页面仅接受 CSV，请使用模板或等待包含该功能的版本。

  1. 保存原始导出文件作为核对依据，上传“账单明细收入”文件。
  2. 如果一分钱记录确实是测试等非经营交易，核实后才勾选相应排除选项。不要仅因金额小就排除真实销售。
  3. 确认收货时间用于归入成交月份；原表没有的付款时间、发货时间和成本保持缺失。
  4. 导入后核对订单数量、金额与来源，继续补成本；非经营记录保留但不计经营利润。

Excel 导入的历史订单不会凭空得到真实采购价，也不会自动恢复平台未返回的收货资料或图片。接口拿不到的历史订单，需要你先取得合法的原始资料。

15 / 日常维护

启停、备份、升级与迁到家用电脑

A 路径的管理命令

在项目根目录执行；自定义过数据目录时，每条都加相同的 -DataDir。

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Start
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Stop
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Restart
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Backup

Stop 保留数据。Backup 会输出备份位置并进行验证；另行安全保存 config.env，因为备份不包含该配置文件。把验证过的备份复制到另一块磁盘，避免只保留在同一块硬盘。

升级前先备份，在新源码根目录运行：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Upgrade

需要恢复时，先保留当前数据的备份，再将下面路径替换为实际备份目录。恢复会替换目标经营数据，只在确认恢复目标后执行：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action Restore -BackupPath 'D:/我的小卖铺数据/backups/实际备份目录' -ConfirmRestore

可设置定时备份：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action ScheduleBackup
# 取消定时备份时执行：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local_release.ps1 -Action RemoveBackupSchedule

默认安排每天 03:00，关机时不能执行；下一次 Start 会检查补备。设置完成后仍应定期查看是否产生有效备份。

B 路径备份与重启

源码方式使用默认本地 Docker PostgreSQL 时，可执行下面命令导出数据库、复制私有文件并在临时库验证恢复：

uv run python manage.py backup_local --verify

默认输出到 .local\backups。先关闭自动同步，安排供货商暂停上传和提交发货，自己也暂停编辑，再执行并检查结果；有并发写入导致校验失败时，先排除写入再重试。另行保存 .env.local。--verify 是恢复验证，不会把备份覆盖到当前业务库。

本命令按 deployment/compose.yaml 中的本地 PostgreSQL 服务工作；自定义外部数据库时不能直接照搬。B 路径当前没有一键生产恢复入口，恢复需要维护人员在独立目标库操作，恢复私有文件与配置后再切换并验证。不要把 A 的 Restore 命令对着 B 环境执行。

电脑重启后，先启动 Docker，再运行 start_local.ps1；已运行时使用 -Restart。该方式没有自动替你安装 Windows 开机服务，也没有改变休眠设置。

迁移到家用电脑：验收顺序

  1. 记录原部署路径、版本、数据位置，完整备份数据库、视频等私有文件和配置。
  2. 在新电脑装相同环境，由对应恢复流程恢复；只复制 HTML 或源码不够。
  3. 确认历史订单数量和关键金额，打开一笔有视频的订单下载原文件。
  4. 验证 API 店铺身份、一次只读同步，再启用自动同步。
  5. 新建公网入口，从外网手机测试上传；向供货商发送新链接。
  6. 确认新环境正常后，停用旧环境自动同步和旧供货商入口，避免两台电脑并行处理。
  7. 配置合适的开机启动、关闭自动睡眠，并实际重启验证恢复能力。
