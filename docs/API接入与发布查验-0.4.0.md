## 本机使用

打开 http://127.0.0.1:8765/integrations/xgj/ ，原账号继续使用。

1. 管理员可验证授权店铺，查看有效期、最近成功时间和自动同步状态。
2. “立即同步”提交后台任务；“重新核对全部可查订单”从第一页重新扫描。失败后可再次提交，已有平台订单按单号去重。
3. 自动同步每 5 分钟执行一次。成功后保存更新时间游标，下次查询保留 10 分钟重叠。每页成功后保存进度，暂时断网最多尝试 3 次；业务错误或重试耗尽会关闭自动同步并显示原因。
4. 平台订单进入待核对列表。打开订单核对商品、数量、成交金额和实际货况，再选择本地商品、实物组及成交单价，生成销售草稿。已有同渠道同单号的销售单直接关联，保留手工数据。
5. 平台变化更新独立快照并保留历史，重新进入待核对状态。较旧及重复数据不覆盖较新记录，缺失或空字段不清空已有内容。
6. 草稿确认、锁库存、发货、到账、退款及利润继续按经营流程处理。平台买家支付和退款金额仅作为核对依据，不自动创建资金流水或推断实际到账。
7. 工作台有待核对数量和连接异常入口。接口不可用时继续使用“导入”和手工订单。

## 推送和数据边界

传输只允许店铺、订单、售后查询路径，固定使用官方 HTTPS 网关并拒绝重定向。签名 URL、密钥及原始错误响应不进入应用日志。本地仅保留核对需要的订单、商品、支付/退款摘要、买家称呼及物流信息，不保存地址、手机号和支付流水号。

公网推送地址为 `https://实际域名/integrations/xgj/push/`。按原始报文验签并检查应用与时间戳，通知先持久化再返回 `result=success`，后台查询详情；重复通知去重，网络失败有限重试，失败通知可手动重试。队列暂不可用时，已接收通知仍可由后续调度处理。

目前没有公网回调地址，已验证的是本地验签、重放、持久化与详情处理，不能记为平台真实公网推送联调通过。

契约依据：[官方签名说明](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/doc-2686716)、[订单列表](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/api-95074856)、[订单推送](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/api-93586387)，以及本地官方 SDK 和本次脱敏实测。

## 启动与恢复

发布镜像 `xianyu-seller:0.4.0` 已用本地已验证的 0.3.0 运行时离线构建，`uv sync --frozen --offline --no-dev` 检查通过；无网络容器执行生产配置检查通过。标准全新构建因公开 wheel 下载缓慢被停止，本次不计为全新在线构建通过。

可复现离线构建：`docker build --network none -f deployment/Dockerfile.offline -t xianyu-seller:0.4.0 .`，前提是本地已有 0.3.0 基线镜像。新机器可按标准 Dockerfile 联网构建，或迁移已构建镜像。

最终备份位于 `.local/backups/20260911-075552-ad89ca`，46 张表恢复校验通过。本次媒体目录为空；视频字节、权限和播放由自动化测试及原恢复记录覆盖。

```powershell
.\.venv\Scripts\python.exe manage.py migrate
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_local.ps1 -Restart
```

独立验证并同步：`.\.venv\Scripts\python.exe manage.py sync_xgj --connect`。增加 `--enable` 开启周期同步。密钥位于 `.env.local`，已排除提交和镜像打包；生产 Web、Worker、Beat 均需配置相同的 `XGJ_APP_KEY` 和 `XGJ_APP_SECRET`。

质量检查与备份：

## 正式本地版仍需的工作

- 按 [PRD V0.6 第 25～27 章](../PRD-闲鱼小卖家后台管理系统-MVP.md)补齐钱货两条线、七类卡点与必要人工录入；原测试结果不代表新增需求通过。
- 完成可分发版本的全新电脑安装、初始化、统一启动/停止、升级保留数据和本地定时同步验收。
- 验证接入起始日过滤、起始日后增量更新、历史手工导入去重，以及售后业务状态和结算字段语义。查询成功不代表这些业务口径已全部确认。
- 核对正式商品、库存和历史账款，选择少量真实新订单进入灰度。平台待核对记录不会自动导入为经营账。
- 在本地正式使用环境验证手机局域网上传、断网经营、休眠/重启补查、备份及另一套安装的恢复。
- 至少连续 7 个自然日核对订单、库存、回款、利润、视频和同步状态，稳定后才标记 M9 完成。

云服务器、域名、HTTPS 公网服务、平台真实推送与云端远程备份改为可选部署能力，不作为正式本地版发布前提。若后续提供云端路径，仍须单独部署与联调，不将本地测试算作云端验证通过。

平台列表最多允许查询 10000 条，更新时间查询有近六个月限制；达到上限或返回越界数据时报错，不标记历史同步完整。中断超过可查询范围时需要历史补录与重新核对。

一张销售单仍对应一种本地商品；商品关联与实物货况由操作员确认。平台数值状态显示原始代码供核对，不将未经业务确认的状态自动映射为本地履约动作。外部发货、改价、退款审批和消息发送未启用。

本版交付的是可本地运行的只读同步与核对流程，不等同于所有平台能力、生产部署或真实灰度完成。
