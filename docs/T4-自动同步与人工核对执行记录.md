# T4 自动同步与人工核对执行记录

日期：2026-09-14。T4 进行中；T4-00、T4-03、T4-05 已完成，T4-01 和 T4-04 完成可离线验证的代码与自动测试，T4-02 及真实授权、休眠恢复验证仍待外部条件。

## 已实现

- Connection 固定首次接入时间和北京时间同步起始日。新连接取首次成功验证当日 00:00；重连、续费、重试不改日期。旧实例优先依据 xgj.connected 审计回填，缺少可信审计时关闭自动同步并要求管理员确认。
- 订单列表继续按 update_time 增量和 10 分钟重叠窗口查询，同时逐条使用 order_time 判断经营范围。接入日后的订单持续接收后续状态；接入日前订单标为历史，创建时间缺失或无效标为范围待核对。
- “重新核对”从固定起始日重扫，不再使用无边界全量窗口。任务记录分别统计扫描、范围内、历史和待核对数量，完整页面结束后才推进连接游标。
- ExternalFactApplication 保存事实类型、外部键、语义版本、内容摘要、目标对象、应用结果和原因。平台订单、独立售后事实及旧售后摘要均有核对记录。
- 已按公开订单契约保存 consign_time、consign_type、运单和快递代码。未知发货方式、发货方式与时间不完整、平台明确清空既有物流字段及取消信息进入待核对，不自动改变本地发货或库存。
- 新增按独立售后编号去重的 PlatformRefund 及版本历史，可保存售后编号、状态、金额、退货物流和原因。缺独立编号的旧详情继续作为摘要待核对，不伪造售后编号，也不自动退款、收货或入库。
- 人工订单、历史导入和 API 使用同一渠道订单号身份。人工先录后同步会自动关联；平台快照先到后导入也会关联应用记录。关联只写元数据，不重放库存、履约或现金事件。
- 工作台直接预览当前平台订单的商品、实付金额、数量和下单时间；平台同步页默认隐藏明确属于接入日前的历史快照。已被后续成功同步覆盖的旧失败只显示恢复计数，具体技术记录由使用者主动展开。
- 闲管家错误 100008 明确提示核对店铺授权及订单 API 套餐，并停止自动重试；本地已有订单、库存和资金数据继续可用。
- SyncRun 增加租约执行者、generation、心跳和过期时间。网络请求不持有经营事务锁；每页入库前再次检查租约 generation。失效旧执行者不能写平台事实或推进游标，调度器可接管过期任务。
- 买家付款、平台退款摘要、交易成功和确认时间仍只用于核对。没有可靠卖家结算来源时，不创建 MoneyEntry，不把平台状态当成卖家到账。
