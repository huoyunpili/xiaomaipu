# M4 首条经营流程验收记录

日期：2026-09-07；版本：0.2.0。

本轮完成自有库存的单商品、整单履约流程，M4 总里程碑仍在进行中。

## 已实现

- 商品仅名称必填；默认货况与实际每件/组货况独立，成色、配件、瑕疵、功能、标签均可自定义。
- 商品默认资料修改不覆盖实物货况；实物货况修改不覆盖历史订单，已锁定货物禁止直接改描述。
- 每次入库生成独立实物组，记录实际采购成本与单件分摊采购运费。数量一致性由每 SKU 的库存余额行锁串行保护，并由数据库约束防止负库存、锁定超过实存。
- 一物一况必须选实际货物；缺货时保留缺口，不跨货况补齐。普通同货况库存按入库先后分配。
- 手工订单保存标题、规格、价格和对外货况快照；内部备注不进入成交说明。订单分配保存实际批次货况及单位成本快照。
- 支持草稿、确认/补锁、取消、快递发货、自提/交付和完成；闲鱼付款和交易成功要人工核对，系统不连接闲管家。
- 发货同时减少实存和锁定，保存实际成本；费用由出库时确认，后续可带原因补录。已完成订单修改费用/退款须管理员。
- 分次收款、退款、应收减免各自留账；超额收款不确认为利润。取消预付订单不会删除已收款，待退款仍可查看。
- 收到退货先增加待检；可售验收独立入库并收回对应成本，报废不回补；现金退款单独处理。
- 关键操作复用事务幂等，审计、业务流水与 Outbox 存储一起提交/回滚；本阶段业务联动同步完成，Outbox 消费尚未启用。

- `python scripts/check.py` 全部通过：81 个 Python 文件格式检查、55 个源文件类型检查、Django 系统检查、迁移漂移检查、**33 项测试通过**。
