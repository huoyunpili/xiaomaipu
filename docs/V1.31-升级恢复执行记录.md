# V1.31 升级与内容恢复演练

执行日期：2026-09-16（北京时间）。本记录使用合成数据及生成的临时数据库，不是正式发行安装验收。

## 已验证范围

1. 创建不含 workbench 的旧版数据库结构，写入旧商品、规格、销售订单、订单明细及描述快照。
2. 执行工作台迁移至 `0006_product_notes`，写入两个店铺共用的商品配置、两代成本、各自订单快照和历史清单。
3. 升级到当前迁移：商品按店铺拆分，成本版本和生效时间保留，原订单单件成本 6000/5000 分及历史清单不变。
4. 再次执行迁移，确认重复启动无数据改写。
5. 保存一张合成 PNG，通过 `backup_local --verify` 实际执行备份、临时数据库恢复和内容比较。
6. 独立执行 `pg_dump`/`pg_restore`，复制私有图片到另一目录，使用恢复库再次启动迁移并核对业务字段。
7. 比较源库与恢复库全部 65 张表的行数及 SHA-256 内容摘要、私有文件哈希。全部一致；旧订单及描述快照断言通过。

数据库名由脚本随机生成，限定 `seller_wb_probe_` 前缀；结束时只删除本次成功创建的临时数据库。合成备份和报告保留在 artifacts 下供复查。

## 复现命令

在已运行项目本地 PostgreSQL 容器的工作区执行：

```powershell
.venv\Scripts\python.exe scripts/verify_workspace_restore.py
```

脚本自动隔离源库、恢复库和私有图片目录，不接受用户提供的生产库作为默认演练目标。它复用 `.env.local` 的本地数据库连接配置，但不会输出其值。

结果文件：

- `artifacts/restore/92caf8fd92f4/report.json`：通过、65 张表、1 张图片、合成数据标志。
- 同目录 `upgrade.json` / `restored.json`：逐表内容摘要和图片哈希。
- 同目录 `command-backups/*/manifest.json`：实际备份命令记录 `content_verified=true`。
- `artifacts/verification-v131-restore-command.txt`：执行日志。

## 内容比较实现

`app/common/backup.py` 将每表记录转为 PostgreSQL JSON 文本，按固定字符排序后流式计算 SHA-256，只返回行数和摘要，不输出订单或联系方式。新增回归用例验证“行数相同、字段被改动”会产生不同摘要。

管理命令 `fingerprint_database` 只读输出当前配置数据库的摘要。`backup_local --verify` 除原有行数与文件哈希检查外，增加源库和恢复库字段内容比较；源库存在并发写入时可能报告不一致，实际备份验证应暂停业务写入。
